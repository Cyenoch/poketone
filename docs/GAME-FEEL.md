# 手感与反馈

调参前先读这里：每个反馈都应能说出依据和层级，而不是凭感觉加特效。

## 依据

| 来源                                                                   | 我们采用的结论                                                                                                                   |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Steve Swink《Game Feel》(2008)                                         | 手感 = 实时控制 + 模拟空间 + 修饰。输入到画面响应要短；移动有起止包络（ADSR），起步、刹车都要快但不能是瞬间的方波。              |
| Martin Jonasson & Petri Purho, "Juice it or lose it" (GDC Europe 2012) | 同一个机制，叠加小而多的反馈（缩放、粒子、声音、震动）后才"有感觉"；每层都要回到静止。                                           |
| Jan Willem Nijman (Vlambeer), "The Art of Screenshake" (2013)          | 打击感清单：命中闪白、击退、停顿（sleep / hit-stop）、震屏、粒子、残留物、低频更重的音效、镜头微推。                             |
| 樱井政博《樱井政博的游戏制作》/ 樱井政博 YouTube 讲座                  | 停顿时长随伤害缩放；被打方在停顿中抖动；音效按重要度分优先级，次要音效可以被挤掉。                                               |
| Jesse Schell《The Art of Game Design》                                 | 反馈必须清晰可读：重要信息（危险预警、血量）在高负载下也不能被淹没。                                                             |
| 本仓库 `.agents/skills/game-feel`、`audio-design`                      | 震屏用衰减的 trauma（平方映射 + 平滑噪声），不用每帧随机抖动；停顿用实时计时，只让最新一次决定恢复；音量按 dB/总线管理并留余量。 |

## 层级与事件

同一局内所有反馈按重要度分三层；新增事件时先归层，再按该层的强度给反馈。

| 层级 | 事件                                                                           | 声音                                                                                                | 停顿                         | 画面                                                             |
| ---- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- | ---------------------------- | ---------------------------------------------------------------- |
| 小   | 普通命中、会心、拾取糖果、冲刺、蓝色出招预警                                   | `hit`（45 ms 冷却）、`crit`（与命中同响度，0.35 s 内合并）、`candy`（连拾音高递增）、`dash`、`tell` | 无                           | 命中闪白、伤害数字弹出（overshoot 缓动）、少量火花               |
| 中   | 反应（感电 / 蒸汽 / 蔓延燃烧）、击倒、树果、升级、受伤、红色出招预警、危险横幅 | `reaction`、`kill`、`berry`、`level`、`hurt`、`tell-danger`、`danger`                               | 无                           | 会心数字放大变黄、反应世界文字、受伤屏幕边缘红闪、低血量边缘呼吸 |
| 大   | 头目 / 精英倒下、守卫倒下、头目 / 守卫出现、宝箱、胜负                         | `elite-kill`（低频）、`boss`、`chest`、`victory` / `defeat`                                         | 精英 90 ms；守卫 350 ms 慢放 | 大粒子、横幅                                                     |

震屏为 trauma 模型（`src/run/view/cameraShake.ts`：玩家受伤 0.25、精英 / 守卫倒下 0.5、守卫冲刺在 8 m 内结束 0.35；trauma² 映射到正弦叠加的偏移，每秒衰减 1.3）；被击中的敌人在闪白期间横向抖动并压扁（樱井），精英与守卫幅度 40%，按真实时间运行，所以停顿中也在抖。

实现位置：音效与音乐 `src/audio/engine.ts`（共享的 Web Audio 引擎，采样来自 `public/audio`，见 [AUDIO.md](AUDIO.md)）；事件到反馈的映射与停顿 `src/run/createRun.ts` 的 `drain` / `hitStop`；伤害数字与边缘红闪 `src/ui/gpu/run-damage-numbers.ts`、`src/ui/gpu/run-edge-glow.ts`；命中闪白、状态色在 `src/run/view/createRunView.ts`；招式特效在 `src/run/view/vfx*`。

## 出招预警（蓝光 / 红光）

敌人开始出招前摇的那一刻，头顶闪一下光、身体闪一下色：蓝 = 普通、躲开就行；红 = 危险。**不做弹反**，颜色只表示「这一下有多要命」，不表示「该按哪个键」。

### 参考

| 游戏 / 来源                                         | 做法                                                                                               | 我们取的                                                                                    |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 《只狼》危（Perilous Attack）                       | 不可格挡的招式前，红色「危」字在玩家头上闪一下，同时有一声专门的提示音；突刺、下段、投技的应对不同 | 红 = 不能硬吃；**形状 + 声音一起**，不只靠颜色                                              |
| 《对马岛之魂》                                      | 敌人武器上闪光：蓝 = 可弹反，红 = 不可挡、只能闪                                                   | 蓝 / 红二分，闪光点在武器 / 头部                                                            |
| 《战神：诸神黄昏》                                  | 敌人身上的圈：黄 = 可挡，红 = 不可挡（多为头目 / 小头目），蓝 = 可打断                             | 红留给头目和精英，保持稀有才有分量                                                          |
| 《匹诺曹的谎言》Fury Attack、《仁王 2》Burst Attack | 精英 / 头目整个身体发红光，表示一记重招                                                            | 身体闪色（我们只闪一下，不持续发光）                                                        |
| 《艾尔登法环》讨论                                  | 前摇长、出手快的「延迟攻击」被批评为难读：信号要说「现在准备」，而不是一直举着                     | 光在前摇**开始**时出现，前摇长度由模拟决定，不做假动作                                      |
| 反应时间经验值                                      | 无干扰 ~200 ms，混战中 400–500 ms；常用公式：预警 ≥ 反应 0.25 s + 闪避起手 + 难度余量              | 我们最短的前摇是酸液 0.35 s（另有 1.1 s 的落点圈），其余 0.6–1 s；光在第 0 帧，给满整个前摇 |
| Xbox 无障碍指南 103、Game Accessibility Guidelines  | 关键信息不能只靠颜色；视觉提示要有非视觉通道（声音）配合                                           | 红比蓝多「!」和双环；红蓝两种声音节奏、音高都不同                                           |
| 本仓库 GAME-FEEL「规则」                            | 混战不能变成噪音，危险预警不能被淹没                                                               | 同屏最多 6 个，红优先、近的优先；地面预警贴花不动、仍画在最上层                             |

来源：[只狼 危（fextralife）](https://sekiroshadowsdietwice.wiki.fextralife.com/Combat)、[只狼 Perilous 分类（ludo.guide）](https://www.ludo.guide/guide/sekiro-shadows-die-twice/core-mechanics/perilous-attacks)、[对马岛之魂 红 / 蓝闪光（Red Bull）](https://www.redbull.com/gb-en/ghost-of-tsushima-boss-battle-tips-guide)、[战神：诸神黄昏 颜色圈（gamepressure）](https://www.gamepressure.com/god-of-war-ragnarok/how-to-react-to-colored-enemy-attacks/z11056e)、[匹诺曹的谎言 红光攻击（SegmentNext）](https://segmentnext.com/lies-of-p-red-attack)、[仁王 2 Burst Counter（GameRevolution）](https://www.gamerevolution.com/guides/638165-how-to-parry-block-burst-counter-in-nioh-2)、[艾尔登法环 延迟攻击讨论（Steam）](https://steamcommunity.com/app/1245620/discussions/0/3719440044270966891)、[预警时长公式](https://silvasessood.blogspot.com/2021/11/combat-design-in-video-games.html)、[反应时间（Engadget）](https://www.engadget.com/2013/09/11/the-art-of-wushu-the-limits-of-human-reaction-time/)、[Xbox Accessibility Guideline 103](https://learn.microsoft.com/en-gb/gaming/accessibility/xbox-accessibility-guidelines/103)。只狼各招的帧数、各游戏的精确时长只有社区资料，没有官方数字。

### 分级（数据驱动）

模拟层在前摇开始的那个 tick 发 `{ t: "tell", enemy, severity, windup }`（`sim/skills/kit.ts` 的 `tell`）。基础等级写在每个招式模块的 `telegraph({ tell, windup, … })` 里（`sim/skills/<招式>.ts`，和前摇放在一起），**精英和守卫一律升为红**，不按物种写死。

| 招式                | 谁           | 前摇             | 等级   | 理由                                   |
| ------------------- | ------------ | ---------------- | ------ | -------------------------------------- |
| 俯冲 `dive`         | 烈雀         | 0.6 s            | 蓝     | 一条窄通道，侧移即躲                   |
| 滚动 `roll`         | 小拳石       | 1 s              | 蓝     | 前摇长，通道清楚                       |
| 酸液 `acid`         | 阿柏蛇       | 0.35 s           | 蓝     | 之后还有 1.1 s 的落点圈                |
| 念力 `psybeam`      | 毛球         | 0.9 s            | 蓝     | 细光束，侧移即躲                       |
| 麻痹粉 `stun-spore` | 派拉斯       | 0.8 s            | **红** | 减速会把玩家留在怪群里连挨打（控制链） |
| 任何招式            | 精英         | 同上             | **红** | 伤害 ×1.6，体型和通道 ×1.9             |
| 冲刺                | 守卫飞天螳螂 | 0.8 s × 难度系数 | **红** | 头目重招                               |
| 空气斩（半血后）    | 守卫飞天螳螂 | 0.7 s × 难度系数 | **红** | 一圈刀，冲刺结束后原地前摇（代替收招） |
| 孢子弹 `spore`      | 走路草       | 无前摇           | 无     | 没有前摇可提示；慢速弹体本身就是预警   |

`tell` 只是表现：不改任何状态，`bun run golden` 不摘要它（它的后果——阶段、预警危险物——已经在摘要里）。

### 表现（`src/run/view/vfx/tells.ts`）

- **蓝**：头部前方一颗四角星闪光（深蓝光晕垫底，浅蓝芯，不用纯白，否则和命中火花分不开），约 60 ms 弹出、0.4 s（或前摇更短时按前摇）内缩小淡出；身体闪蓝一下（40 ms 升、220 ms 落）。
- **红**：更大的红星 + 两圈先后（相隔 160 ms）向外扩散的环 + 头顶描边的「!」，「!」一直留到前摇结束；身体连闪两下红。
- 身体闪色走现有的实例颜色（和受击闪白、状态染色同一处），没有新材质。
- 同屏最多 6 个：先红后蓝，同级按离玩家距离；距玩家 17 m 外不画。精灵从现有粒子系统的即时精灵里预留 30 个（其他效果整帧用不到这些位置），在所有即时精灵之后最后画，所以不会被招式、状态标记或弹幕盖住，也不会被挤掉预算。
- **声音**（`src/audio/engine.ts` 的 `RULES` + ElevenLabs 素材 `tell` / `tell-danger`）：蓝 `tell` 是一下钝的木质轻敲（四条轮换，带 ±6% 音高抖动，重音在 30–80 ms，小一档响度）；红 `tell-danger` 是两下空心木桶敲击（三条轮换，重音在 20–30 ms，中一档响度，冷却内退回蓝色）。两者都不是纯音：纯音铃声式的预警在一秒响几次时就是“叮叮叮”（见 [LESSONS.md](LESSONS.md)「音频」）。节奏、音色都不同。两者都不让位于发声上限；冷却 0.3 / 0.45 s，只有 14 m 内的前摇出声（`createRun.ts` `drain`）。素材未经人耳试听。

## 敌人血条与伤害数字

- **血条**（`src/run/view/healthBars.ts`，一次实例化绘制）：只在受伤后出现，最后一次受击 2.2 秒后淡出；普通敌人细、精英略粗，守卫用 HUD 大血条。掉血时被扣掉的那段先变白再转黄、向上下溢出血条边缘（约 2.3 倍高度，停顿期间保持，随后缓出收回），停 0.35 秒后收缩到当前血量（格斗游戏 / ARPG 常见的"延迟血条"）；死亡时血条闪亮并向外放大淡出（0.32 秒）。
- **伤害数字**：世界空间抛物线（随机横向初速 + 上抛 + 重力），字号按伤害的对数缩放（0.85–1.6 倍），深蓝描边；会心更大、带橙色光晕、轻微倾斜、停留更久。每帧最多新增 5 个、同屏最多 30 个，会心不受每帧上限限制。位置与弹出动画分在两个节点上（见 `docs/LESSONS.md`）。

## 规则

- 反馈不直接改写玩法状态；重要事件的停顿放慢本机模拟推进和画面，联机共享世界由房主推进。普通受伤不触发全局减速，震屏只动相机。
- 成群敌人时不能变成噪音：每个音效有冷却，总发声数有上限（14），低层音效在满载时让位。
- 设置里可关闭音效；偏好存于 `localStorage` 的 `poketone.settings.v3`。
