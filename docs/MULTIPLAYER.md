# 联机运行与排查

当前合作规则只在 [multiplayer](../openspec/specs/multiplayer/spec.md) 维护；传输、重连、owner、快照和播放状态的实现定位见 [网络地图](state-machines/network.md)。本页说明如何开始和排查，不维护协议版本演进或第二套任务表。

## 开始一局

单机不需要服务。合作时各端使用相同构建和服务入口，由一人建房、其他人输入六位房间码；二至四人完成连接后房主选择地图/难度并出发。不要求等满四人，也没有独立准备开关。大厅成员离开只移除其席位。合作中菜单和地图只影响本人，共享世界不会暂停。

Web使用当前origin的联机入口。native开发启动及 `--harbor` 参数见 [运行手册](NATIVE-RUNTIME.md)。直连可用时走直连，否则由Harbor中转；服务变量、证书/代理和部署步骤只维护在 [Harbor](../services/harbor/README.md) 与 [部署手册](../deploy/README.md)。

## 断线与失败

进行中的对局重返需要房主进程和Harbor房间仍存活，且使用有效凭据及匹配构建。断线、刷新或直连失败只影响该席位，其他人继续游戏并看到提示；先看页面区分正在载入与真正重连；不要用重新建房代替仍可恢复的会话。房间已经丢失或构建不匹配时按明确错误重新组队。

诊断时记录房主/客机角色、人数、构建、地图/区、所走传输以及发生阶段。区分握手失败、地图恢复、资源准备、输入归属、播放积压和终局交付；网络地图给出各自的状态所有者。日志若包含重返凭据不要公开提交。

退出时页面可以先返回大厅；连接只保留本席位必要交付；已确认的离开者可以断开，Harbor 将缺席者的终局最多保留十分钟，收齐确认可提前释放房间。可选重返缓存失败会提示，但不阻止当前连接；诊断时应区分它与主存档失败。

## 聚焦检查与证据

```sh
bun run test:network
bun test scripts/snapshot.test.mjs scripts/coop.test.mjs
```

测试可按改动范围选择。旧预测/带宽基准不当作当前协议的性能。

本机内存或Harbor测试不能替代WAN/NAT/TURN、多设备长局和物理设备；复测计划归对应change，本文不维护平行验收矩阵。
