# 渲染：环境与角色

`src/run/view/` 把模拟状态画成一帧。原则：一个场景、一盏投影太阳光、全部用 three 自带材质（Lambert）加 `onBeforeCompile` 补丁，不用渲染目标做全屏后处理（调色写进色调映射，暗角是一次乘法混合，见「画风」）；能在 CPU 上算一次的东西（地面图层、植被摆放）开局烘焙，每帧只更新少量 uniform。相机会被 Q/E 旋转，所有着色都不能假设固定视角。

## 关卡外观（`stageThemes.ts`）

模拟层的 `StageDef` 只说地图里有什么（`content/stages/`），画面层按 `world.stage` 查 `stageThemes` 决定怎么画，目前只有森林。主题里放的是换一张图就会变的东西：

- `haze`：雾色（同时是 `scene.background`）与雾的远近；`light`：天光、地面反光、太阳颜色与强度、太阳相对视野中心的位置（决定影子长度）。
- `ground`：草坪、草甸、泥土、崖面四张贴图的地址与各自的 `settle`（饱和度、线性色调），水边的湿泥、小石子、水底颜色；`water`：水洼各色带。
- `props`：每种道具的模型、风中摇摆（顶端偏移、频率）、是否按面着色、颜色倍数、绘制尺寸相对碰撞尺寸、是否投影。
- `minimap`：小地图的梯田色带、水、岸、场外的墙。

各地图内容与敌人模型由内容注册表驱动；主题入口与具体字段以 `src/run/view/stageThemes.ts`、`src/run/sim/content/` 为准，不再使用单地图时期的扩展预留说明。

## 画风：调色、光照、暗角

方向来自一张森林小镇等距微缩景观的参考图：饱满的中、暗绿（暗部是深而仍有颜色的蓝绿，受光的草是偏暖的黄橄榄），局部对比强（阳光块挨着阴影块、草里一簇簇深色杂草），树冠是一团团圆叶，顶亮底暗；红、白、粉的小花点缀；四角压暗，像打了光、浮在暗处的微缩景观。「安静」靠冷暖色相和明暗结构，不靠降饱和；角色、招式和预警保持原色。

- **调色**（`grade.ts`）：改写 three 的 `CustomToneMapping`；世界的绘制与编译都包在 `inWorldPass` 里（`renderer.toneMapping = CustomToneMapping`、曝光 1.25，结束后回到 UI 的 `NoToneMapping`），因为世界与 UI 共用一个 renderer。它是每个内置材质（Lambert / Basic）的最后一步光照运算，所以不需要渲染目标、额外绘制或带宽，MSAA 与半透明混合都不变。线性色依次经过：
  1. 「绿色领先」（g 明显高于 r、b）的颜色饱和度只降 25%，去掉青柠味；橙、紫、红、青蓝几乎不受影响。
  2. 冷暖分离：暗部 ×(0.8, 0.97, 1.1) 偏蓝绿，受光处 ×(1.07, 1.02, 0.9) 偏金。
  3. 在近似显示空间（平方根）做 50% 的 S 曲线：暗部更沉，中间调拉开，亮部有一点肩部（超过 1 的值先截断）。
- **不经过调色的**：招式特效、血条、边界墙是自写着色器，直接输出显示色，不包含色调映射片段，所以保持原有饱和度。雾在色调映射之后混入，所以雾色直接给调过色的颜色（森林 `#93a69c`，24–72 m，画面上沿有一层淡淡的雾，`stageThemes.forest.haze`）；`scene.background` 用同一个颜色。
- **暗角**：一个全屏三角形，乘法混合（`dst × v`），`renderOrder 0.5`：在不透明场景、水面（−1）和圆形影子（0）之后，在招式特效（1+）、玩家剪影、边界墙和血条之前。所以四角的预警仍然是全亮度。中心到 0.7 不变，边中点约 ×0.78（敌人从这里进场），四角约 ×(0.4, 0.45, 0.48)，偏深青。乘法暗角与alpha/加法混合一般不可交换：预乘源色S、目标色D、alpha a和系数v满足 `v × (S + (1−a) × D) ≠ S + (1−a) × v × D`。当前顺序有意保留后绘VFX亮度，不等价于对最终整帧统一加暗角。手机只支持横屏，没有按宽高比修正。
- **光照**（森林，`stageThemes.forest.light`）：天光 `#b9d2e6` / 地面反光 `#38482f`、强度 1.6 → 1.0；太阳 `#ffd9a0`（偏金）、2.9 → 3.9。阴影只剩偏蓝的天光，所以深而冷；受光的地面暖而亮。阴影软化见「阴影」。
- **局部对比**：
  - 草地细节按贴图均值放大 1.6 倍对比（深草簇与亮点，均色不变）。
  - 草地上撒一层细碎的深色杂草斑（`envNoise(p × 11)` 的阈值，最深 ×(0.55, 0.7, 0.64)），泥土坡会盖掉它。
  - 约四分之一的草丛是深蓝绿的「杂草」（顶点里按草丛随机数选，×(0.48, 0.64, 0.6)）。
  - `groundMacro` 的湿 / 干漂移加宽：湿处更暗更冷，干处更暖更亮。
- **地面配色**（`stageThemes.forest.ground`）：草坪 / 草甸的 `settle` 饱和度 0.75 / 0.72，色调偏黄（色相约 95° → 90°）、比旧版略亮。
- **遮蔽**：地面遮蔽偏蓝绿（`groundOcclusion`），道具脚下的接触阴影 0.55 → 0.8，范围加大（树 1.9、松 1.6、灌木 1.25 倍尺寸）；草根压到 55%；敌人的圆形影子 `#10262a`、不透明度 0.27。不做 SSAO。
- **花**：白、黄、粉、深红（罂粟），比草更饱和；花带之外，道具脚下的遮蔽圈和洼地也聚花（见「植被」）。
- **水**：浅水更亮的青绿，加一层很弱的自发光（`waterGlow`，只在浅处）。在阴影和云影下，水洼仍然是一汪亮水。

| 第一版（偏灰，已替换） | 0.35–0.43–0.49   | 0.38         | 94°             |

实测（2026-11-04，Apple M5 Pro，无头 Chrome，种子 424242，`time = 500` 后约 117 只敌人，**暂停模拟**，让每帧画面完全相同。每页 3 × 3 s 的 GPU 计时查询中位数，各配置跑 2 页。「改动后」是冻结的基线副本只叠加本次的渲染文件和道具模型，没有混入其他 agent 的改动）：

| 配置   | 桌面 1280×720                            | 手机视口 780×360 @2（画布 1170×540） |
| ------ | ---------------------------------------- | ------------------------------------ |
| 改动前 | 2.32–2.81 ms（另一页 3.7–3.9，机器负载） | 2.29–2.35 ms                         |
| 改动后 | 3.11–3.21 ms                             | 2.59–2.63 ms                         |

- 合计约 +0.3–0.4 ms（桌面）/ +0.27–0.3 ms（手机视口）。上一轮拆开测过：暗角约 +0.05–0.1 ms，调色约 +0.05–0.2 ms；其余来自草地杂草斑、多一次草地均值采样和更多花。
- 4× CPU 节流、手机视口、不暂停：requestAnimationFrame 回调耗时中位数改动前 3.1–3.3 ms，改动后 3.1–3.2 ms，没有差别。调色只多一次着色器编译，没有每帧 CPU 工作。
- **未在真机手机上测过**：调色和杂草斑是逐片元 ALU，开销随过度绘制（草）增长，中端手机 GPU 上的比例可能比这里大。

没做或降级的：SSAO（用烘焙遮蔽和圆形影子代替）；渲染目标式后处理（`EffectComposer` / `postprocessing`：多一次全屏读写和 MSAA 解析，还会把特效洗白，见 `docs/LESSONS.md`）；像素 / 抖动质感（在我们的低多边形模型上没有能让它成立的廉价做法，只有阴影软化带来的细颗粒和杂草斑）；泛光。

## 风

`src/run/sim/wind.ts` 是纯函数，不在 `World` 里存状态，所以联机各端、各系统读到的是同一阵风：

```ts
windAt(seed: number, time: number): { dirX: number; dirZ: number; strength: number; gust: number }
```

- `dirX / dirZ`：风吹向的单位向量。每局有一个主导方向，约一分钟内缓慢偏转最多 ~70°。
- `strength`：持续风力 0.3–0.75（永不完全静止）。
- `gust`：0–1 的阵风，每几秒一次涌起又平息。
- 由种子决定、C1 连续（值噪声 + smoothstep），不用 `Math.random`。以后要做弹道偏移、飞行单位漂移时直接调用它。

画面层每帧用 `world.seed / world.time` 求一次风，写进共享 uniform（`environment/wind.ts`）。`uWindScroll` 是沿风向累计的位移：阵风团和云影跟着它平移，所以风向转动时图案不会跳。

着色器里只有一个入口 `windLean(p, phase, rate)`：返回根部在 `p` 的物体每单位高度的水平倾斜。阵风团（约 12 m 的噪声团）顺风滚过整片草地，叠加每个根部自己的相位抖动；`rate` 决定抖动快慢（草 2.6，花 1.9，灌木 1.6，树 1.1，松 0.9）。

## 地面

开局在高度图网格（0.5 m）上烘焙一张 RGBA8 图层纹理，地形着色、植被根部颜色、植被摆放读的是同一份数据：

| 通道     | 含义                                                                                                                                         |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| r 草甸   | 三叶草与小花的草甸斑块（低频噪声）                                                                                                           |
| g 泥土   | **就是导航的 `groundBlockedMask(nav)`**：地面单位爬不上去的格子。可玩区外没有规则，用同一个判据（地形坡度 > 地面类 climb），边界处不会有接缝 |
| b 草密度 | 洼地更密、可走的陡坡变稀、道具脚下清空                                                                                                       |
| a 遮蔽   | 洼地、坡脚、道具脚下的接触阴影                                                                                                               |

另有一张半精度 **离岸距离**纹理（`shore`，4 纹素 / m）：每个纹素到最近水洼设计轮廓的带符号距离（模拟层的 `shoreDistance`，水下为负），只算水洼附近，其余读作干地。地形画岸、植被根部压暗、水面裁剪和分色带都读它（`SHORE_GLSL` 的 `groundShore`）。草和草甸的密度仍按模拟层的水深在水下和水线以上几厘米清零。

地形片元着色器（`terrain.ts`）：

1. **可走地面**：草地贴图用 Quilez 的防重复采样（两份错位副本按慢噪声交叉淡化），草甸斑块只在 r 有值处采样；再乘一层低频的「湿润 / 干燥」宏观变化和每层梯田极轻的色相偏移（高处偏暖、洼地偏冷，亮度不变）。**高度不靠提亮表达**：旧版每升一层就提亮、偏黄，崖边再提亮 20%，高台因此发白，已删除。
2. **泥土坡**：g 通道 > 0 处画泥土——较缓的坡用俯视泥土，越陡越偏向侧投影的土层（X / Z 两面按朝向混合，地层保持水平），从坡脚到坡顶由暗到亮。掩码按 0.5 m 一格，边缘用 5 次采样把格子台阶磨圆，直线边缘的 0.5 等值线（规则边界）不动；再用噪声打散，偏移不超过一格的几分之一。坡顶有一条很窄的亮草沿。
3. **遮蔽**：a 通道按 `groundOcclusion` 压向冷的蓝绿（满值 ×(0.42, 0.53, 0.58)），不是变灰；道具脚下最深 0.8。
4. **剪影墨线**（已认可，保持不变）：只在背向相机下坠的边上画，线宽随落差和朝向变化；朝向相机的坡不画线。

## 植被

两次实例化绘制：

| 层  | 每个实例            | 内容                                                                                                                                                        |
| --- | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 草  | 30 顶点 / 18 三角形 | 6 片两段式锥形叶片组成一丛；高草丛（大尺寸）在噪声团和洼地里聚集，叶尖偏麦秆色                                                                              |
| 花  | 35 顶点 / 20 三角形 | 一个茎 + 6 片菱形花瓣 + 六边形花心，顶点着色器按种类改形状：白雏菊、黄毛茛（杯状）、粉色秋英、红罂粟（浅杯、深色花心）、三叶草（隔一片花瓣隐藏 → 三片圆叶） |

- **摆放**（开局在 CPU 上，按种子确定）：草按图层 b 通道的概率撒点；芦苇只长在水边（离轮廓 −0.35…0.12 m），且只在慢噪声挑中的几段岸上成丛，每张图约 10–100 丛（20 个种子），每丛 5 片叶 25 个三角形，按设备密度缩放；花沿每局随机轴向的拉长噪声成片、成带出现，不均匀撒；种类按梯田层（洼地多毛茛，中层雏菊、秋英和罂粟，高台罂粟）加低频区域选择，再混入 12% 的杂色；花带之外，道具脚下的遮蔽圈和洼地也会聚起花（烘焙遮蔽 0.25–0.55 处最多 60% 的概率）；三叶草铺在草甸斑块上。泥土格、道具脚下、坡面上都不长；离水洼轮廓（`shoreDistance`，水面着色器画的同一个轮廓）草丛 0.45 m、花 0.4 m（湿泥带最宽处）以内不长；建筑地基（`world.map.pads` 及其过渡边）保持纯草坪：没有花、三叶草和高草丛。
- **配色**：白、黄、粉、深红四种，比草地更饱和，是画面里的小块点缀；花头 10–20 cm、离地 5–30 cm，不发光。不用青色和蓝色（经验糖果是青蓝八面体）。红罂粟偏深红而不是橙红，又小又暗，和大面积、发亮、会动的红色预警分得开。
- **颜色与光照**：叶片和花茎的根部取脚下可走地面的平均色（同一个 `soilColor`），根部再压到 55%、叶尖变亮，每片叶子亮度有 ±20% 的差异（草地的明暗颗粒）；法线一律取地面法线（双面相同），所以根部与地面无缝衔接、背光坡上的草不会发亮。花瓣带区域色相漂移，高台略偏冷。
- **动态**：风（`windLean`，弯曲随高度平方增长并保持叶长）、玩家走过时向外倒伏、离相机 38–44 m 时缩小到 0：刚好在画面外（平地上屏幕远角离相机 31–36 m），画面里看不到植物变小。
- **裁剪**（`chunkedInstances.ts`）：8 m 区块；视锥内且在 44 m 内的区块打包到一个实例属性的前段，一层一次绘制。只有出现「可见但未打包」的区块时才重新打包（带 4 m 余量），镜头抖动不会每帧重传。
- **密度**：桌面草丛 4 丛 / m²（乘草密度），花在花带内约 5 株 / m²；粗指针设备（手机、平板）全部乘 0.6。

## 水洼

`world.map.water.puddles` 由 `environment/water.ts` 画成一次透明实例化绘制：每个水洼一个盖住整个开挖范围（`radius`）的圆盘，片元着色器读地面的离岸距离纹理（见「地面」），在岸外丢弃。不读地形高度：半米的高度网格双线性插值出来的等高线是折线，岸线会出现棱角。圆盘画在水面以上 4 cm，因为地形网格在采样点之间是线性的，轮廓内侧个别三角形会比水面高一点，否则深度测试会在水线上切出折角。风格参考 Wind Waker 与 Roystan 的卡通水：平涂、按深浅分色带、不做反射和折射。目标是「水坐在洼地里」，不是贴在草上的一块贴花：岸由地形画，水边是透明的。

- **岸（地形着色器）**：离水 1.6 m 内草地逐渐压暗偏冷（`groundDamp`，植被根部用同一个函数，叶片和地面一起变暗）；水线外是一条深橄榄褐的湿泥（`WET_SOIL`，泥土贴图只给纹理），宽度沿岸由慢噪声决定，0–0.4 m（`MUD_BANK`），有些地方草直接接到水边；泥和草的边界跟着草地贴图的明暗走，像草簇伸到泥上；露出水面的泥上有少量灰色小石子。泥一直延伸到水下，0.45 m 内过渡到深绿的池底（`POND_BED`）。不用泥土坡的橙褐：那个颜色在这个游戏里表示「走不了」。
- **水边**：一层透明的薄水，不透明度从水线处的 6% 升到浅水的 50%，过渡宽度沿岸在 0.06–0.34 m 之间变化，颜色从深青（`WATER_EDGE`）过渡到浅水色，透出下面的湿泥。菲涅耳和自发光也跟着这层薄水淡出，否则水边会是一圈灰白。
- **色带**：按离岸距离分浅、中（青绿）、深三层，边界用 1 像素宽的抗锯齿阶跃，并用噪声抖动；只有够宽的池塘才有深色心。不用青蓝（经验糖果的颜色）。
- **白沫**：只在慢噪声挑中的几段岸上，离水线 5 cm 处一条约 5 cm 宽（至少约 2 像素）的细线，再被高频噪声打成虚线；这些岸段缓慢漂移。没有整圈的白边。
- **焦散**：两层反向漂移的值噪声，取「两层值相等」处的细线，形成摆动的网状亮纹；只在中、深水，很淡。
- **反光**：天空色的菲涅耳；阳光闪点是稀疏的小亮片，在光照里乘太阳直射光，阴影和云影下消失。浅处有一层很弱的自发光，阴天也是一汪亮水。
- **涉水**：玩家和地面敌人站在水里时（`waterDepthAt`），离镜头最近的 12 个产生向外扩散的波纹法线和一圈泡沫。只读位置，不改模拟。
- **绘制顺序**：不写深度、`renderOrder = −1`，先于技能地面贴花、预警和圆形影子绘制，预警叠在水面之上仍然清楚；水下的角色腿部被水面盖住，像在蹚水。
- **植物**：草丛根部离轮廓至少 0.45 m（叶展 + 5 cm，量到着色器画的同一个轮廓），花离开湿泥带；芦苇反过来只长在水边，根可以在浅水里。
- **小地图**：水用比地面略深的灰青（`minimapBake.ts`），读作地形而不是标记。

## 预算与实测

预算：植被三次绘制（芦苇每张图最多约 100 丛），水面一次；地形片元在普通草地上是 9 次高度 + 1 次图层 + 2 次草地贴图 + 1 次草甸均值（另有 three 阴影的 5 次采样，与改动前相同），草甸、泥土坡、坡边各自只在出现处追加；每帧 CPU 新增只有一次风求值、两层各 225 个区块的视锥测试，以及有新区块进入视野时的重新打包。

| 改动后，开局 | 19       | 51.8 万    | 0.98–1.40 ms               | 1.15–1.68 ms                  |
| 改动前，混战 | 20       | 54.0 万    | 1.12–1.27 ms               | 1.85 / 2.46 / 2.69 ms         |

### 状态与反应（`vfx/status.ts`）

- 带状态的身体除了原有整体染色，还有持续标记，每种状态占身体上固定一处，叠加不重叠：灼伤 = 上身 3 簇上升缩小的火苗；麻痹 = 身上每秒几次黄色星形电花，染色同拍闪；睡眠 = 头顶描边「Z」向斜上飘；湿润 = 下身落地水滴，蓝色染色缓慢闪；中毒 = 身上冒出会破的紫泡 + 淡紫光（敌人另有紫色染色）。玩家的麻痹粉减速复用麻痹电花。标记和染色都按状态 id 查表（`MARK`、`statusTint`），读的是 `statuses` 列表。
- 每个身体同时最多显示 2 种，优先级 睡眠 > 麻痹 > 灼伤 > 湿润 > 中毒（染色优先级 睡眠 > 麻痹 > 灼伤 > 中毒 > 湿润）；第 3、4 种每 1.4 秒轮换第二个位置。
- 全部是现有粒子系统里的单帧精灵，由时间和身体 id 算出形态：无粒子状态、无新网格 / 材质 / 绘制调用、无每帧分配。每帧另留 720 个精灵预算（不挤招式）；拥挤时每个身体标记变少，再不够时固定比例的身体保留标记（不闪烁）；距玩家 17 米外不画。敌方危险预警仍画在最上层。
- 反应：`vfx.ts` 按事件的 `reaction` id 查表分发。感电 = 3.5 米真实溅射半径的青色圈 + 贴地电弧 + 带电水滴；蒸汽 = 橙闪转白 + 短白汽柱与低云 + 2.8 米圈（第一版遮挡敌人约 1 秒，已减薄）；蔓延燃烧 = 2.8 米圈与火焰 + 飞向圈边、边飞边焦黑的燃烧叶片。
- 实测（300 只敌人、每 tick 重挂状态，固定种子）：1280×720 与 780×360@2 都 60 fps；4× 节流下每帧 CPU 2.6–2.8 → 2.9–3.2 ms，GPU 无可测变化。
- 已知缺口：敌人可以中毒，但还没有招式挂毒；同伴没有状态。

### 出招预警（`vfx/tells.ts`）

敌人前摇开始时的蓝 / 红闪光与身体闪色，设计与分级见 [GAME-FEEL.md](GAME-FEEL.md)「出招预警」。实现上：一个固定 128 项的对象池（无每帧分配），`select` 在画敌人之前跑，所以闪光和身体闪色同一帧开始；身体闪色写进已有的实例颜色；精灵从即时精灵里预留 30 个（最多 6 个预警 × 5）：`Sprites` 整帧把这些位置扣住，`release()` 后预警最后画，画在其他效果之上。新增一种精灵形状「!」（`Shape.bang`，和「Z」同样描边）。

实测（2026-11-05，Apple M5 Pro，无头 Chrome 1280×720，DPR 1，种子 424242，玩家周围 200 只敌人、同时 4–11 个在前摇；「改前」是本次开工前整个仓库的快照，「改后」是当前仓库，含其他人同期的改动；交替各跑 2 页 × 3 次 5 s）：两者都锁 60 fps，requestAnimationFrame 回调中位数不节流都是 0.8–0.9 ms；4× CPU 节流改前 3.4–3.8 ms、改后 3.1–4.2 ms，在同组波动内，没有测出差别（机器负载约 6）。

## GPU 上传与 context 丢失

context 恢复后 three 换了一套资源管理器，丢失前上传的资源仍挂着旧管理器的 dispose 监听，之后释放会在新 context 上删除失效句柄（[LESSONS.md](LESSONS.md)「context 恢复后再开一局」）。规则：

- 唯一的监听者是 `src/rendering/app-renderer.ts`：丢失时停帧、`generation++`，对登记的 resident（app-host、对局）依次 `release()`；恢复时重设通道默认状态、`restore()`、不补算丢失期间的时间。只释放 GPU 副本，CPU 对象保留，恢复后自动重传；不调 `preventDefault`（three 已经调了）。
- 场景树用 `releaseUploads(root)`（`src/rendering/releaseUploads.ts`）；它看不到树外的对象和只在 `onBeforeCompile` 闭包里的贴图。
- 释放只用 GPU 那一半：实例缓冲按 three 公开的 `isInstancedMesh` 标志识别（UI kit 的面板、字形网格也设了这个标志，但不是 `InstancedMesh` 子类），只派发 `dispose` 事件、单独释放 `morphTexture`；不调用这类对象自己的 `dispose()`，它们会改 CPU 状态（three 置空 `morphTexture`，UI kit 摘掉矩阵更新钩子）。
- UI 侧的拥有者：各个 `UiStage`（含公开的 `Text.fontSignal.value?.page` 字体页），由 app-host 的 resident 释放；小地图与罗盘的闭包贴图由对局的 resident 释放。
- 凡是持有这类上传的拥有者都要提供 `releaseUploads()`：现在是 `RunView`、`RunAssets`、`LoadedModel`。新增闭包贴图、对象池或离屏资源时，把它加进拥有者的 `releaseUploads()`。

## 已知限制

- 导航掩码是逐格的：陡度刚好在 climb 附近的缓坡会出现断续的一两格泥土。这是规则本身的形状，画面如实显示；要更连贯得在掩码或规则上做（例如形态学闭运算），属于导航侧。
- 妙蛙种子只有一段四足步行动画，速度换算顶到 5 倍上限后仍有一条腿轻微打滑；需要一段真正的跑步动画。
