# 平衡分析手册

数值修改从 [唯一数据索引](../src/run/sim/content/README.md) 开始；玩法契约见 [combat-builds](../openspec/specs/combat-builds/spec.md) 与 [world-progression](../openspec/specs/world-progression/spec.md)。本页只解释分析工具；数值以模拟内容表和模型源码为准，不复制另一份参数表。

## 运行

```sh
# 难度 0/1/2；研究所 none/mid/slots4/luck/party；默认完整六关
bun run balance:model 0 none
# 单图分析从新玩家开始，用于局部对照，不代表正式路线后图构筑
bun run balance:model 0 none forest 1
# 首关按参考时间挑战，后图进图30秒挑战；等级由连续成长决定
bun run balance:model 0 none campaign 1 510,30,30,30,30,30
# 机器人仅用于森林走位策略校准，参数以脚本入口为准
bun run balance 0 8
bun test scripts/model.test.mjs scripts/model-survival.test.mjs
```

CLI 参数见 [balance-model.ts](../scripts/balance-model.ts)。输出分 novice / average / expert，每分钟观察等级、输出、受伤压力、生存分布与守卫耗时；模型预设和目标区间是分析假设，不是玩家验收或阻塞门禁。

## 如何判断

先在同一源码、内容表、种子、研究所、路线或单图分析模式下比较前后结果，记录构建身份。用同一参考点比较招式/道具预算，再观察成长和生存曲线。不要同时改变多个参数后把全部差异归给其中一个。

解析模型以存量/流量和期望几何近似推进；离散构筑按种子抽样，先推进每份样本再汇总。机器人覆盖运动和地形，但代表特定策略；真人自然长局才提供真实操作与难度反馈。这三种证据不能互相替代。

`guardian fights` 的 `completed/attempted` 是已击杀/已进入守卫战的样本数。`seconds` 与 `cost`（预期承伤折合最大生命）只对已击杀样本求均值，没有击杀时显示未完成，不把提前死亡截断的消耗当作整场读数。前后完成样本不同会产生幸存样本偏差，比较时必须一并看完成数、通关概率与耗时。追加落点的首次施放、原生招式阶段等待和麻痹延迟采用解析近似；其节拍可能高估或低估实际模拟，不能直接用 `cost` 证明难度倍数。

输出中的 `pressure = capacity / incoming` 实际是清怪供需比：分子为满容量场景下、仅玩家自身构筑的有效清怪能力（HP/s），分母为常规刷新带入的敌人生命（HP/s，含动态供给倍率但未扣活怪上限阻止的生成）。大于1表示理论能力超过供应，小于1表示供应超过能力；它不等于实际受压程度，也不直接控制正式对局刷怪。判断时还要看场上存量、接近时间、精英/守卫分流、同伴、终极技、受伤与生存，不能把该比值强制锁到1。

生命调优从目标击杀耗时反推参考耐久：参考有效单体输出（HP/s）×目标交战秒数，再对照实际物种抗性、可攻击时段及爆发。群怪另看清怪供需与围攻存量。参考构筑用于离线校准；不要把玩家本局每次增伤等比例转换成敌人生命。每次候选都要完整重跑成长，因为击杀变慢会改变经验、宝箱和后续构筑。

运行时增援压力的参数入口为 `content/params/pacing.ts`，实现为 `sim/director-pressure.ts`；`spawnScale` 单独输出最终普通供给倍率。模型共用目标、平滑和供给公式，但使用既有密度与命中率近似观测：均匀密度对距离权重积分得到邻近数量，平稳泊松命中假设得到近期受伤期望。真实空间聚集和伤害突发可能不同，不能把模型的动态反馈当作实局控制器验收。与旧版本比较时须注明是否包含动态增援，历史静态候选结果不代表新闭环。

## 证据与限制

历史数值、公式取舍和校准输出不在仓库中保留；新实验在对应change登记实际日期和基线，不往本手册追加流水账。

守卫经验与宝箱、神奇糖果即时升级已接入模型。模型仍以敌池平均、聚合存量和几何近似计算；真实旧怪保留出生时生命，模型普通怪存量不逐只记录出生年龄。不能据模型单独下自然通关率结论。受控目标/状态数增伤已计入守卫输出，但通用睡眠唤醒、冻结/诅咒易伤及真实冷却相位仍未完整重建，需用正式伤害函数校准相应构筑。

调生命时同时看森林开局、两分钟、八分钟和每张后续地图入口。固定构筑对比用于解释伤害与耐久，全程模型用于检查击杀变慢后的经验、宝箱、捕获与成长反馈。头目批次按自身生命成本消耗，额外血量不能换算成更多击杀或奖励；同伴继续读取原共享成长曲线。

## 连续六关与 AI（2026-11-10）

正式关卡是森林、沙漠、海岸、冰川、火山、紫苑塔，各图一个完整场地；六次关卡正常阶段各至多十分钟，狂暴允许超时。`campaign:true` 用同一构筑与 HP 分布沿六图推进，`zoneClears` 提供每图守卫到达/完成概率、完成等级和累计时间；`fights` 与路线一一对应。默认每图在固定参考时点召唤；CLI 可指定逐关召唤秒数，不计加载、选卡和人类寻找出口的等待。守卫出生生命、伤害及速度始终按玩法参数 `GUARDIAN_REFERENCE_SECONDS` 校准；改变召唤时点只改变实际经历的成长与战场，不给予早召属性折扣，也不限制玩家等级。

路线参数从 `params/campaign.ts` 读取，后图敌人生命时钟有固定下限，避免转场回到薄皮开局；不读取玩家装备来抵消成长。同伴仍使用原有共享成长，不跟随敌人专用耐久一起膨胀。经验、进化及本线招式门槛来自正式模拟定义，模型连续结算前图奖励。

预判与侧移由真实速度、攻击轨迹、反应延迟和地形共同决定；解析模型的 `skill.dodge`、典型命中与聚合场地没有重建这些几何。这些画像尚未用人类数据重拟合，不能把输出概率称作人类通关率，也不能从局部命中对照推导整局难度倍数。

固定守卫基准、精英/头目耐久调整已与不同召唤时点对照过（2026-11-12）。参考时点用于离线校准，不是玩家挑战门槛；不保证任意构筑获胜或固定击杀耗时。
