# 平衡分析手册

数值修改从 [唯一数据索引](../src/run/sim/content/README.md) 开始；玩法契约见 [combat-builds](../openspec/specs/combat-builds/spec.md) 与 [world-progression](../openspec/specs/world-progression/spec.md)。本页只解释分析工具；数值以模拟内容表和模型源码为准，不复制另一份参数表。

## 运行

```sh
# 难度 0/1/2，研究所 none/mid/slots4/luck/party，默认比较四条完整路线
bun run balance:model 0 none
# 单图分析从新玩家开始，用于局部对照，不代表正式路线后图构筑
bun run balance:model 0 none forest 0
# 首关按参考时间挑战，后图进图30秒挑战；等级由连续成长决定
bun run balance:model 0 none campaign 0 510,30,30,30
# 同一连续构筑比较野外事件开启/关闭，并输出逐图收益与模型假设
bun scripts/balance-field-events.ts 0 8 --json
# 同路线与种子下，把 none 换成 all 或逗号分隔的规则 ID；分开看原始收入和结算星沙
BALANCE_RULES=level-cap,alpha-elites bun run balance:model 0 none campaign --json
# 机器人仅用于森林走位策略校准，参数以脚本入口为准
bun run balance 0 8
bun test scripts/model.test.mjs scripts/model-survival.test.mjs
```

CLI 参数见 [balance-model.ts](../scripts/balance-model.ts)。输出分 novice / average / expert，每分钟观察等级、输出、受伤压力、生存分布与守卫耗时；模型预设和目标区间是分析假设，不是玩家验收或阻塞门禁。

## 如何判断

先在同一源码、内容表、种子、研究所、路线或单图分析模式下比较前后结果，记录构建身份。用同一参考点比较招式/道具预算，再观察成长和生存曲线。不要同时改变多个参数后把全部差异归给其中一个。

解析模型以存量/流量和期望几何近似推进；离散构筑按种子抽样，先推进每份样本再汇总。机器人覆盖运动和地形，但代表特定策略；真人自然长局才提供真实操作与难度反馈。这三种证据不能互相替代。

`guardian fights` 的 `completed/attempted` 是已击杀/已进入守卫战的样本数。`seconds` 与 `cost`（预期承伤折合最大生命）只对已击杀样本求均值，没有击杀时显示未完成，不把提前死亡截断的消耗当作整场读数。前后完成样本不同会产生幸存样本偏差，比较时必须一并看完成数、通关概率与耗时。追加落点的首次施放、原生招式阶段等待和麻痹延迟采用解析近似；其节拍可能高估或低估实际模拟，不能直接用 `cost` 证明难度倍数。

输出中的 `pressure = capacity / incoming` 实际是清怪供需比：分子为满容量场景下、仅玩家自身构筑的有效清怪能力（HP/s），分母为常规刷新带入的敌人生命（HP/s，含动态供给倍率但未扣活怪上限阻止的生成）。大于1表示理论能力超过供应，小于1表示供应超过能力；它不等于实际受压程度，也不直接控制正式对局刷怪。判断时还要看场上存量、接近时间、精英/守卫分流、同伴、终极技、受伤与生存，不能把该比值强制锁到1。

生命调优从目标击杀耗时反推参考耐久：参考有效单体输出（HP/s）×目标交战秒数，再对照实际物种抗性、可攻击时段及爆发。群怪另看清怪供需与围攻存量。参考构筑用于离线校准；不要把玩家本局每次增伤等比例转换成敌人生命。每次候选都要完整重跑成长，因为击杀变慢会改变经验、宝箱和后续构筑。

运行时增援压力的参数入口为 `content/params/pacing.ts`，实现为 `sim/director-pressure.ts`；`spawnScale` 单独输出最终普通供给倍率。模型共用目标、平滑和供给公式，但使用既有密度与命中率近似观测：均匀密度对距离权重积分得到邻近数量，平稳泊松命中假设得到近期受伤期望。真实空间聚集和伤害突发可能不同，不能把模型的动态反馈当作实局控制器验收。与旧版本比较时须注明是否包含动态增援，历史静态候选结果不代表新闭环。

## 证据与限制

历史数值、公式取舍和校准输出不在仓库中保留；新实验在对应change登记实际日期和基线，不往本手册追加流水账。

野外对照脚本使用同种子的连续构筑，`fieldEvents:false` 只关闭额外事件机制，主线节拍仍按正式时间窗抽取。事件经验、宝箱、同伴和星星沙子在发生的分析步消费，影响后续等级、输出和存活；`income` 是机制归因，`earned` 是实际收益，不能把两者再加到总账。携带蛋跨图保留，满栏孵化卡不经过地上宝箱的拾取概率。地图探索率、引导受击中断和战斗分流属于画像假设，详见该模块的 `FIELD_MODEL_ASSUMPTIONS` 与 `FIELD_MODEL_LIMITS`。CLI 可用 `BALANCE_FIELD_EVENTS=0` 关闭额外机制做配对诊断，不能将不同种子或不同样本数混为前后对照。

终极技读取正式准备与保护时长，准备期间不提前兑现伤害，脉冲按分析步与时间线的交集结算。报告的施放、释放、保护秒数和避免伤害用于核对时序与 HP 过程；瞬时接敌、状态唤醒和空间命中仍是模型近似。

守卫经验与宝箱、神奇糖果即时升级已接入模型。模型仍以敌池平均、聚合存量和几何近似计算；真实旧怪保留出生时生命，模型普通怪存量不逐只记录出生年龄。不能据模型单独下自然通关率结论。受控目标/状态数增伤已计入守卫输出，但通用睡眠唤醒、冻结易伤及真实冷却相位仍未完整重建；诅咒已按占用率近似，需用正式伤害函数校准相应构筑。

调生命时同时看森林开局、两分钟、八分钟和每张后续地图入口。固定构筑对比用于解释伤害与耐久，全程模型用于检查击杀变慢后的经验、宝箱、捕获与成长反馈。头目批次按自身生命成本消耗，额外血量不能换算成更多击杀或奖励；同伴继续读取原共享成长曲线。

## 终极技：危机充能

`bun scripts/balance-crisis.ts` 配对比较同一小火龙、森林 → 沙漠 → 冰川 → 紫苑塔、每图 510 秒召唤、关闭野外事件。默认 16 个构筑种子（起点 `0x5eed`）。仅切换危机来源，时间与输出充能保持不变。

| 画像（关闭 → 开启）   |  清怪供需比 |      施放次数 |        通关概率 |    平均存活秒数 |
| --------------------- | ----------: | ------------: | --------------: | --------------: |
| 普通，无研究，average | 1.33 → 1.27 | 28.13 → 39.44 | 13.75% → 18.82% | 1340.0 → 1355.2 |
| 困难，无研究，average | 2.44 → 2.11 | 28.00 → 39.44 | 17.50% → 18.41% | 1016.9 → 1040.4 |
| 普通，满研究，expert  | 6.83 → 7.05 | 31.19 → 31.94 | 99.99% → 99.99% | 2061.7 → 2058.9 |

施放次数是模型推进的构筑轨迹均值，生存和通关则按生命概率分布结算。困难档基线平均少活 323 秒；供需比高并不等于承伤重。受压两组多放约 11 次，强构筑平均不到一次；生存时间包括提前通关结束。小样本会随施放时序分叉，差异较小的概率不宜外推。

把每条失血的充能系数单独从 0.45 提到 0.50，同样 16 个种子的困难档通关为 18.97%，但平均存活从 1040.4 秒降至 1033.5 秒；强构筑施放次数不变。保留较低的 0.45：已有两档受压收益，没有一致证据支持额外奖励承伤。

[正式参数](../src/run/sim/content/params/ultimates.ts)让损失一条最大生命换回略低于半条终极技，单只守卫不触发围攻。贴身敌群只计超过门槛的部分，围攻每秒受限，与受伤共享从首次入账起的个人窗口；无论治疗、装备倍率或跨窗爆发，都不能靠相邻两窗单独充满一条。解析器以一秒的穿盾期望承伤和敌方毒伤估算失血，以密度在近身圆内的积分和守卫接近概率估算可见近敌；不逐个模拟遮挡、方向、毒伤触底、瞬时伤害和实际按键，非真人通关率。

## 分岔路线与 AI

森林起步，在沙漠与海岸、冰川与火山各选一张，最后进入紫苑塔。`campaign` 比较这四条组合，每个样本将构筑和生命分布连续带过四张图。`zoneClears` 给出各图到达守卫、击败守卫的概率、完成等级和累计时间。`fights` 记录对应的守卫交战。各图正常阶段至多十分钟，狂暴后可超时。可按图指定召唤秒数，守卫生命、伤害与速度统一读取 `GUARDIAN_REFERENCE_SECONDS`。

路线参数从 `params/campaign.ts` 读取，后图入图时钟在短暂升温后同时承接怪群生命、伤害、速度、刷新、容量与同伴成长；不读取玩家装备来抵消成长。敌人专用耐久倍率仍不应用于同伴。经验、进化及本线招式门槛来自正式模拟定义，模型连续结算前图奖励。

`campaign` 报告把后图前两分钟与前图离开前两分钟并列，同时给出召唤守卫前的纯怪群窗口。窗口读取逐秒探针，按当时存活概率加权；同时看普通/精英存量、积压生命、清怪供需、落地承伤与条件存活。前图末窗包含守卫战，不能把它的承伤全部归于怪群；召唤当秒不计入纯怪群窗口。提前离图造成的截断会标为未完成，完全没有观测时显示为空。调整前后须使用相同种子数、角色和召唤时点；候选与正式模型的小样本数不同，不能当成等条件前后对照。

预判与侧移由真实速度、攻击轨迹、反应延迟和地形共同决定；解析模型的 `skill.dodge`、典型命中与聚合场地没有重建这些几何。这些画像尚未用人类数据重拟合，不能把输出概率称作人类通关率，也不能从局部命中对照推导整局难度倍数。

固定守卫基准、精英/头目耐久调整已与不同召唤时点对照过（2026-11-12）。参考时点用于离线校准，不是玩家挑战门槛；不保证任意构筑获胜或固定击杀耗时。

## 羁绊

```sh
BALANCE_STARTERS=charmander bun scripts/balance-bond.ts 0   # 单线；省略则九线串行，很慢
bun run balance:model 0 mid campaign 0 510,510,510,510 --bond   # 默认不输出羁绊块；--bond 追加，很慢
bun test --timeout=0 ./scripts/model-bond.test.mjs
```

[bond.ts](../src/run/balance/bond.ts) 定义对照臂和容差，[balance-bond.ts](../scripts/balance-bond.ts) 输出；效果在 `runModel` 的 `bond: { level, lab }`。同一四条路线、同一批种子，average 画像，32 个样本，开局 510 秒召唤，难度普通。模型处理：

- **挺住**：多一枚致命保留 1 HP 的限次保命，带 `PLAYER_IFRAMES`。模型按“后备”排在其他保命之后，保命总次数不变，只与复活类保命换了顺序（正式模拟里挺住最先消耗）。
- **自己治好**：每图一次，移除第一段中毒（5 秒的持续伤害）。持续场地会在下一步重新施加，所以这是上限；价值只有约 8 点生命一张图，模型里与 Lv2 几乎无差别。灼伤、减速等其他异常不在玩家模型中，未估算。
- **节点**：Lv3 起把 `bondLabModifier` 并入研究所增益，与正式 `createWorld` 同一份数据。

容差（提示而非门禁）：满羁绊相对同研究所无羁绊，单个伙伴通关至多 +14 个百分点；九线均值通关至多 +8 个百分点、压力指数至多 ×1.05。挺住这一条命本身约 +3–6，所以容差不能低于这个量；研究所 10 级（`mid`）相对无研究所约 +16，满羁绊约为其 3/8，且满研究所下被封顶（见下）。

研究所 `mid`（10 级）：九线均值 40.6% → 44.9% → 44.9% → 46.8%（+6.2，单线最大 +10 小火龙）。满研究所（所有通用节点满级）：98.7% → 99.3%（+0.1），模型被封顶，羁绊不再是变量。三档的压力指数均值比分别为 0.993 / 1.040 / 1.014，均在 ×1.05 内；单线噪声可达 ±0.1（如凯西 `mid` 0.85），因此只看均值。鬼斯、皮卡丘的节点读数为零甚至为负，属于 32 样本的路径分叉噪声，不能据此调节点。

改前（`BOND_LAB_HP`=3）与改后只有迷你龙不同：无研究所 Δ+7% → +8%，`mid` +5% → +6%，其余各格相同。

每局点数 = （清图数期望 + 6 × 通关概率）× 难度倍率，再扣取整损失约 0.5，取九线四路线均值（正式规则见 add-partner-bond/design.md）：

| none   | 3.0  | 2.8  | 2.7  | 3.3／10／20／33／53       | 59            |
| mid    | 4.6  | 5.3  | 5.0  | 2.2／6.5／13／22／35      | 32            |

设计里的“普通约 16 局、噩梦约 8 局到满级”只在接近满清的局成立（满研究所）；中等和更弱的玩家要 2–3 倍。点数公式没改，是否放宽里程碑另行决定。

## 训练师

```sh
BALANCE_STARTERS=charmander bun scripts/balance-trainer.ts 0   # 单线；省略则九线串行，很慢（可按线并行）
bun run balance:model 0 mid campaign 0 510,510,510,510 --trainer   # 默认不输出；--trainer 追加
bun test --timeout=0 ./scripts/model-trainer.test.mjs
```

[trainer.ts](../src/run/balance/trainer.ts) 把四种道具折成按 90 秒冷却的平均收益，在 `deepStats` 里并入属性（`RunOptions.trainer`）；[trainer-report.ts](../src/run/balance/trainer-report.ts) 和 [balance-trainer.ts](../scripts/balance-trainer.ts) 输出对照。设定：average 画像、研究所 `mid`、四条路线、32 样本、单人。

- **速度强化**：移动 +20%、攻速 +15%，占空比 8/90，折成移动 ×1.018、冷却 ÷1.013。
- **要害攻击**：6 秒必定要害，占空比 6/90，把暴击率向 1 推进该占空比。
- **好伤药**：每次 12% 最大生命，折成每秒 `0.12 × 最大生命 / 90` 的再生，经正常的溢出和治疗倍率结算。队友在半径内同样获益，单人模型不计。
- **万灵药**：4 秒免疫加解除当前异常，折成毒伤消耗 −7%（免疫 4 秒 + 当前一段约 2.5 秒）。减速等其他异常不在玩家模型内，未估算。
- **同伴**：伤害 ×1.15、攻击间隔 ×0.9，即同伴每秒输出 ×1.278。
- **巧修**：遗忘返还 +50%，满级（8 级）招式多返 20 星星沙子，纯经济，不入战斗。
- **远眺、博物**：非战斗（小地图读取距离、异色率与遇见计数），不入模型。

折算的是“冷却一好就用”的无偏平均。玩家会选时机：好伤药和万灵药在危急时刻价值高于平均，要害攻击在守卫战价值高于平均；这些选时红利没有建模，所以道具的真实价值比下表大且方差大。

## 对战塔

```sh
bun run balance:tower 8 0x5eed        # 也可省略样本数和种子；显示每 7 层及首末层
bun run balance:tower 8 0xc0ffee
bun run balance:tower 8 0xdecaf
bun run balance:tower 8 0x5eed --json # 导出逐层数据；可替换种子
```

`balance:model 0 none tower 3` 只分析远征的紫苑塔单图。`balance:tower` 读正式模型和 [TOWER 参数](../src/run/sim/content/params/tower.ts)，用同一条种子地图序列跑普通／困难、小火龙／妙蛙种子四组。每组 8 个固定种子构筑，单人 `average`，无研究所加成、背包或挑战规则；分析覆盖完整内容池，不校准局外解锁进度。

模型按 1 秒步长推进同一构筑和生命分布，层间保留成长、道具和同伴。普通层压缩节拍与事件窗口，怪物名单仍用原局部秒数，难度的固定提前量不缩放；守卫层首秒开战，不压缩模板，不进暴走。每次守卫通过计入回复、经验、宝箱、奖杯并重置事件抽取记录。计时结束或击败守卫即估作离开，不计赶往出口、清场拾取和载入；刷怪、命中、走位、站点与承伤沿用解析近似，事件和卡牌用分析样本自己的种子流，不复刻正式世界 RNG 消耗或联机。守卫超过地图原时长加分析加时仍未分胜负时单列截尾。第 50 层仅是分析范围。

复现基线时，在同一版代码中将 `hp/dmg/guardianHp/clock` 斜率系数设为 `1/1/1/1`，`guardianHealthBonus` 设为 `1`，其余使用现值，再跑相同命令。校准靠守卫层额外耐久拉长前段战斗，原有守卫生命与伤害共用的 1.25× 加成保留；从第 23 层开始加快生命和伤害的线性外推。入图时钟的末段斜率为零，经验倍率仍停在远征最后一步。

## 七条玩家线的校准

新增三线沿用参考基础属性的衰减比例：形态 HP 按基础 HP 比值的平方根增长，速度与接触半径分别按基础速度、身高比值的四次根增长。新线起始半径为 0.36 u，进化显示高度也压缩为四次根；最终输入只维护在 `content/lines/*.ts`，推导与声画交接见 [三线设计](../openspec/changes/add-ghost-dragon-fighting-starters/design.md)。

以下为加入三线时的分析参考点：无研究、无背包、完整六关、每关 510 秒召唤守卫、average 画像、32 个固定种子构筑样本。每个数是同一构筑连续走完六图的解析通关概率，不是人类实测或产品门禁；对照所用模型包含毒伤刷新与诅咒占用估算。

状态模型仍有边界：毒与灼伤在守卫上分别按最强施加命中和刷新占用率计算，诅咒按占用率近似易伤；群怪 DoT 在单次施放内合并，跨招式共享同一存活目标的精确相位尚未重建，可能高估重叠施毒。终极技的状态占用与唤醒时点也未逐脉冲重放。上述概率用于判断相对强弱，正式走位和声画仍需实际游戏验收。

## 特性、留形与天气构筑

用 `BALANCE_DEEP_BUILD` 指定配对样本。逐图对照 `buildFields` 的期望存活秒数、群怪/单守卫 HP/s、自施天气占用率，以及 `zoneClears` 的守卫到达/击败概率；`outcome.clear` 是末图通关概率。输出是按当前存量和存活样本加权的构筑能力；守卫实际交战另看 `fights`，不能用全图估值除以守卫生命替代。`evolutions` 记录实际推进的阶段，`tradeWait` 从达标开始计时，`evolvedAt:null` 表示样本结束仍未换形。

```sh
# 旧版：冻结源码，不切换分支；使用同一组默认种子。
baseline=$(mktemp -d)
git archive 122a2b3d src scripts package.json | tar -x -C "$baseline"
(cd "$baseline" && BALANCE_FIELD_EVENTS=0 BALANCE_SAMPLES=8 bun run balance:model 0 none campaign 0 510,510,510,510 --json) > before.json
# 改后：在当前源码或其冻结副本运行；JSON 固定 average 画像。
deep() {
  BALANCE_FIELD_EVENTS=0 BALANCE_SAMPLES=8 BALANCE_STARTERS="$1" BALANCE_DEEP_BUILD="$2" \
    bun run balance:model 0 none "${3:-campaign}" 0 "${4:-510,510,510,510}" --json
}
deep charmander,bulbasaur,squirtle,pikachu,gastly,dratini,machop,abra,geodude '{"slot":0}' > after.json
jq '.rows[] | select(.route == ["forest","desert","glacier","tower"]) | {starter, zoneClears, buildFields, tradeWait, outcome}' after.json
jq '.rows | group_by(.starter)[] | {starter: .[0].starter, meanClear: (map(.outcome.clear) | add / length)}' before.json after.json
deep bulbasaur '{"slot":0,"form":"everstone-eviolite"}'
deep pikachu '{"slot":0,"form":"light-ball"}' # 对照 pikachu、thunder-stone
deep abra,gastly,geodude,machop '{"slot":0,"tradeDelay":0}' # 与奖杯路线比较；也可改为 120 秒
deep geodude '{"slot":1}'
deep charmander '{"slot":"hidden","weather":"sun","weatherRock":true}' forest 510
deep charmander '{"slot":"hidden","weather":"sun","weatherRock":true,"solarCost":0.02}' forest 510
deep charmander '{"slot":0,"pledge":true,"pledgePartner":"bulbasaur"}' forest 510
bun test scripts/model-deep-builds.test.mjs
```

留形保留进化奇石资格，也保留未解锁招式的机会成本；正常进化样本不选不变之石。比较普通栏位 `0`、`1` 时，第二栏要到第一次进化才生效；`hidden` 视为开局已用特性膏药。单人通信样本在最后进化前为联系绳留一格，仍可能从升级卡提前拿到；每图击败守卫并结算经验和普通宝箱后，符合正式资格时取奖杯的保底联系绳、进化并腾出道具栏。样本未达标或没打过守卫就不会提前获得这份保底；奖杯其他选项不计。指定 `tradeDelay` 则只看达标后的固定交换时点，不走联系绳。即时交换样本无留格成本，两者之差还包括道具栏和选卡路径，不能全算成等待损失。

天气对照用同一隐藏特性，分别跑不预装天气、`weatherRock:false` 和 `weatherRock:true`；`weatherUptime` 是乘岩石前的名义占用率，实际值受覆盖、整秒采样与样本存活影响。`solarCost` 可试太阳之力每晴秒的最大生命消耗比例。天气近似不模拟冷却成长、连续操作和跨图冷却相位。配对誓约另报组合频率与场地占用，不计入单席路线；更换 `pledgePartner` 对照火海、彩虹、湿地，省略伙伴则只算本席招式。参数、折算和未建模项见 [deep-builds.ts](../src/run/balance/deep-builds.ts) 的输出说明。

## 超级进化（add-mega-evolution 1.1 / 1.2）

模型把超级形态当作最终形态之后的一个阶段（`src/run/balance/mega.ts`，对照输出 `scripts/balance-mega.ts`，`bun run balance:model` 在含小火龙时一并打印）。sim 里还没有这套内容，下表的数值是给实现者照抄的建议值，全部以模型内常量 `MEGA_PARAMS` 为准。

### 建议数值

| 项目                             | 超级喷火龙Ｘ             | 超级喷火龙Ｙ                               |
| -------------------------------- | ------------------------ | ------------------------------------------ |
| 最大生命（相对喷火龙）           | +14                      | +10                                        |
| 速度                             | +0                       | +0                                         |
| 伤害方向（形态自带修正，非特性） | 护甲 +8                  | 特殊招式伤害 ×1.35                         |
| 特性                             | 硬爪：物理招式伤害 ×1.30 | 日照：超级进化时和每次入图施放 30 秒大晴天 |
| 习得招式                         | 闪焰冲锋                 | 日光束（沿用现有数值）                     |

闪焰冲锋：火系、物理波，威力 50、冷却 3.2 秒、10% 灼伤；反作用为每次命中施放损失 0.2% 最大生命，非致死（与中毒同一下限）。几何和升级项沿用龙之俯冲。

模型假设：进化石在第 2 张图守卫奖杯取得，占 1 个道具栏（背包满时丢弃最低等级道具）；喷火龙形态下进入超级形态，只补新增最大生命并获得进化无敌；超级特性替换原特性（猛火、太阳之力的数值被精确撤销）；新招额外占 1 格招式栏。`replace`（顶替升级最少的招式）会让超级进化净为负收益，因此招式栏已满的现行规则下，实现必须给额外格子或直接授予。

日照只按天气占用率近似：30 秒窗口占一张图时长的约 5–6%，加上入图重施后模型内自施天气占用约 11–15%（对照无超级进化的 6–11%）。它几乎不影响结果，Ｙ 的优势来自 ×1.35。速度同样不敏感，取 0。

### 敏感度与调参过程

- 闪焰冲锋反作用是最敏感的杠杆：每次命中 1.5% 时Ｘ的通关率塌缩，取 0.2%。
- 闪焰冲锋威力 38（冷却 3.2）时 Ｘ 落后 Ｙ 约 3–5 个百分点，威力 50 时差距收敛到 2 个百分点以内，所以取 50。
- Ｘ 与 Ｙ 的通关率差距：均值不到 1 个百分点，单条路线最多 2–3 个百分点（样本噪声同量级），没有任何一边在所有路线上占优。
- 超级进化整体抬升约 +2–6 个百分点通关率，位于「后期有明显抬升、不破预算」的范围内。

### 局限

- 闪焰冲锋预算（budget.ts 口径，与全体招式中位数之比，目标 0.6–1.4×）：群怪 3.42×、守卫 2.18×，含硬爪 4.45× / 2.84×。口径偏高，原因是该口径的参照点（第 3 步图）本身就让波类招式偏高：同一参照点龙之俯冲为 1.99×/1.27×，日光束 3.81×/1.63×。相对龙之俯冲，闪焰冲锋是 1.56 倍（由威力与冷却比决定）。没有按中位数压低，因为压低后Ｘ明显弱于Ｙ，见上；若要严格落进 0.6–1.4×，需要同时抬高Ｘ的其它项。
- 候选池中的第二招（龙之俯冲、暴风）未建模；日照与求雨、野外天气的互相覆盖按"最后生效者"近似；超级形态的属性（火/龙、火/飞行）只影响天气伤害免疫，受击克制未建模。
- 压力指数不是门禁（见上文）；以上结果是单人 average 画像，不含多人。
