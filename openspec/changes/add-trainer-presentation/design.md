# Design

## Context

需求见 proposal。当前 `GpuLobby` 已有决定列与自定义焦点导航；`LobbyPick` 是导出存档以外的本机便利偏好。房间的 `PlayerSetup` 直接取纯模拟 `RunConfig`，没有训练师字段。`createRun.start()` 负责世界预热、声音准备、联机 ready 屏障及激活；`drain()` 已收到实际 `ult`、进化、清区等事件，联机提供事件年龄与去重。HUD 使用同一 GPU 舞台，正常 UI 不走 DOM。

相关依据：`DESIGN.md`、`docs/STATE-MACHINES.md`、`docs/state-machines/network.md` 及共享 UI 未完成验收。工作区存在其他人的大厅、特效和模拟改动，实施采用局部修改并保留原差异。

## Goals / Non-Goals

**Goals:** 角色选择从大厅一直传至房间、开局、局内演出；素材与代码结构便于继续添加表情；开局真实释放模型且多人可安全等待。

**Non-Goals:** 训练师实体、移动、战斗加成、主动技能、技能树、衣橱、存档迁移；不建立通用剧情图或新动画引擎。

## Decisions

1. **形象元数据与模拟分离。** 建立静态训练师表及稳定 ID，`LobbyPick` 增加选择；多人 `PlayerSetup` 在协议层扩展纯模拟配置，训练师不进入 Player、快照或 RNG。这样同一玩法种子和指令保持原结果，不因外观重录 golden。
2. **大厅沿用决定列。** 追加一行可见姓名与角色头像的选择，使用现有按钮和焦点规则，紧凑布局随决定列滚动。房间席位补训练师名，允许重复选择，身份仍由 P1–P4 决定。
3. **共享切入组件。** 参照用户截图的左侧人物越界、深色斜切横带、角色名及短句；采用项目深海蓝与各角色配色，文字由 GPU 绘制。开局短时间放大，战斗中收在边缘，终极技快进快退；单一显示槽按优先级取舍，不排长队。
4. **投球在 run 激活前。** 场景预热后先完成本地开局持久化，显示冻结世界并播放投球弧线、球壳开启、光环与模型显现；本机演出结束再提交现有 ready 屏障。绘制时钟驱动，失焦/context loss 不积欠时间，销毁解除等待；换区和恢复明确跳过开局。
5. **消费已有事件。** 终极技只由实际 `ult` 事件触发，沿用 `eventAgeMs`，不监听按键推测成功。普通对白来自局内时间间隔和重要个人事件，使用独立表现冷却与固定轮换，不调用模拟 RNG。模态/地图/错误/换区/结束清理装饰；危险消息抑制普通对白。
6. **素材与准备。** 每个角色独立目录保存源图与后续表情；沿用既有图像来源提取或生成透明立绘，输出 `public/art/trainers/<id>/`，同目录 provenance。通过 ImageStore 准备上传，发布继续由 art 内容哈希管线处理。
7. **夏装造型重设。** 当前角色方向以 [原创训练师设定](../../../assets/concepts/original-trainers/README.md) 的 summer-v2 为准：澄汐白丝双马尾美少女、夜苇黑丝御姐、朔野清爽少年系帅哥，三人均为 18 岁成年人，采用年轻日式角色面容和夏装，气质差异通过姿态与穿搭体现。新设定图另存，第一版原始来源保留；发布立绘需从新造型派生并重新检查，概念图完成不视为大厅与演出资产已替换。
8. **第四人夏晴与解锁。** 夏晴为 18 岁的邻家姐姐气质角色，白皙肤色、栗棕侧马尾与雏菊发饰，采用贴身清凉但关键部位完整遮盖的夏装。解锁只读取 `Progress.kills >= 5000`，不增加存档字段或货币消费。大厅永久保留她的入口，锁定时头像与大立绘使用同一源图派生的纯色剪影，并显示累计击败进度；预览与实际选择分离，预览锁定角色不写入偏好或对局配置。联机个人选择沿用同一门槛，队友展示按其有效角色身份呈现，不按本机进度遮挡他人。

## Risks / Trade-offs

- [开局 ready 顺序可能导致冻结或客机先受伤] → 使用同一 ready 屏障，测试慢席位、离线与恢复，正式多人启动验证。
- [战斗人物条遮挡危险或触控] → 限定边缘面积、短时长、单槽与危险优先，桌面及横屏截图和动态检查。
- [图片背景边缘或表情裁切] → 查看透明结果的深浅底表现并记录派生坐标，保留原图。
- [并行工作区变化] → 核对最新源码与局部差异；最终验证报告注明实际范围，物理设备和正式 native App 单独记录。
