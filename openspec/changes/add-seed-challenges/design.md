# Design

## 所属版本

大版本「野外与路线」第 11 项，共用约定见 `add-field-events/design.md` 总表。依赖 `extend-progress-v5`；规则段依赖 `add-challenge-rules`，模式段依赖 `add-battle-tower`。

## 复现前提

- 同一份 `RunConfig`（种子、难度、模式、起始地图、规则、伙伴与加成）在同一模拟版本下，单人局在相同指令下结果一致；不同玩家的操作不同，所以比的是"同一局面下谁打得更好"，不是录像回放。
- 模拟版本指纹已存在：`scripts/game-build.ts` 对 `src/run/sim/**/*.ts` 求 sha256 取前 16 位十六进制，作为 `__GAME_BUILD__` 注入 Web 与原生，联机房间也用它。种子码取其中前 8 位（32 位）。只改界面、渲染或音频不改变指纹，种子码继续有效；改了模拟就失效。
- 内容表在 `sim/` 内，因此 ID 的顺序也被指纹覆盖：码里可以用内容表下标代替字符串 ID。

## 编码

按位打包后用 Crockford Base32（不含 I、L、O、U，大小写不敏感）输出，每 5 个字符一组用 `-` 分隔，前缀 `PT`：

| 段       | 位数 | 内容                                                                     |
| -------- | ---- | ------------------------------------------------------------------------ |
| 格式版本 | 4    | 当前为 1；码格式变化时加一                                               |
| 版本指纹 | 32   | `__GAME_BUILD__` 前 8 位十六进制                                         |
| 种子     | 32   | `RunConfig.seed`（现由 `crypto.getRandomValues` 生成的 32 位无符号整数） |
| 难度     | 2    | 三档下标                                                                 |
| 模式     | 2    | `expedition` / `tower`                                                   |
| 起始地图 | 3    | 地图表下标（对战塔模式忽略）                                             |
| 规则     | 16   | 规则表下标的位掩码；`add-challenge-rules` 之前为 0                       |
| 伙伴     | 8    | 0 为任选，否则为伙伴表下标 + 1                                           |
| 校验和   | 16   | 以上各段的 CRC-16/CCITT                                                  |

共 115 位，补零到 120 位即 24 个字符，加前缀写作 `PT-XXXXX-XXXXX-XXXXX-XXXXX-XXXX`。解码时忽略空格、大小写与分隔符，便于从聊天软件里粘贴。

`src/run/seed-code.ts` 只做纯函数 `encodeSeedCode(config, build)` / `decodeSeedCode(text, build)`，返回配置或带原因的错误：`format`（字符非法或长度不对）、`checksum`、`version`（格式版本不认识）、`build`（版本指纹不同）、`content`（下标越界）。界面按原因显示一句话，例如"这个种子码来自另一个游戏版本"。

## 公平开局

- 种子挑战的 `RunConfig.players[*]` 不带研究所加成（`lab` 省略）、背包装备（`Loadout` 为空）与羁绊效果（`bond` 为 0），研究所内容解锁按全部未解锁处理（事件池、交互点、出口标记、隐藏特性候选都用基础内容），所有人从同一起点出发；对局结算的星星沙子、击败数、羁绊点等局外奖励照常发放。
- 训练师不编码进种子码，由玩家自选，和“任选伙伴”一样记录在成绩里。复现条件因此是：同一种子码、同一伙伴、同一训练师、同样的操作。
- 固定伙伴时，每位玩家都使用该伙伴；任选时各自选择，成绩记录带上所用伙伴。
- 难度必须已解锁才能出发；未解锁时显示锁定，不改写码里的难度。

## 联机

- 房主输入种子码，房间配置由码决定；加入者看到同样的解码结果。联机的版本指纹检查已有（`network/session.ts`），种子码的指纹检查只在房主解码时做一次。
- 结算时每位玩家各自把成绩写进自己的 `seeds`。

## 记录

- 进度 v5 `seeds`：最近 20 条 `{ code, starter, trainer, result, time, kills, floor? }`（`floor` 只用于对战塔码，为通过的层数），新的在前，超出时丢弃最旧的；同一个码可以有多条。
- 大厅种子挑战页显示最近记录；选中一条可再次复制该码或以它出发，并显示该码在本机的最好成绩：远征码胜利优先、用时更短，失败比坚持时间；对战塔码比通过的层数，层数相同比用时更短。

## 界面

- 大厅模式选择旁加入"种子挑战"子页面：
  - **新种子**：用当前大厅选择生成新种子码，显示并可复制（`TextServices.writeClipboard`）。
  - **输入**：GPU 文本框（`TextServices.createInput`，Web 端用 IME 覆盖层），以及"粘贴"（`readClipboard`）。输入变化时即时解码，合法时展示地图、难度、模式、规则与伙伴的图标，不合法时文本框标红并显示原因。
  - **出发**：走大厅一次出发流程。
- 结算界面：种子挑战局显示"复制种子码"；普通局也可复制本局种子码，作为"把这局分享给朋友"。
- 新增界面文字通过 `test:ui` 字形检查；键鼠、触控、手柄都能完成输入（手柄依靠粘贴；存档导入已取消屏幕键盘，若手柄需要逐位输入，实现时另行设计）。

## 不做

- 不做服务器、排行榜、成绩上传或成绩签名防作弊。
- 不做录像回放。
- 不兼容旧版本的种子码（版本指纹不同即拒绝）。
