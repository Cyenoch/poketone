# Design

## Context

沿用 `DESIGN.md` 的地图标记、席位色、边缘危险消息与屏外指示；正式画面由共享 GPU 路径绘制。需求见 proposal。模拟 `alive`、救援状态和可靠事件已提供必要事实，无需新增网络状态机。

## Goals / Non-Goals

让玩家在召唤前后都能找到守卫，并立即辨认需要救援的队友；不改变死亡、个人复活与救援速度，不增加常驻解释文字。

## Decisions

- 召唤地标和存活守卫共用带「守卫」标签的红金徽记，清区后恢复出口色。用现有 MapInk 形状和描边文字，避免新增图像资源；圈外按方向贴边。
- 倒地展示只读取 `alive` 与 `departed`，世界救援圈和光柱穿透场景遮挡；屏外标记沿用安全区和 HUD 避让规则。
- `damagePlayer` 仅在实际倒下时清除救援，非致死受击保留进度。有个人复活次数时不创建倒地警报；其余合作倒地事件由房主经可靠通道传递，玩家动作包不得提交。消息显示前检查当前是否已复活或离队，使用 P 编号区分同种伙伴。
- 房主在每步共享模拟后捕获实际倒地/复活事件，及时更换客机生命代次；即使同帧倒地后清区救回、最终 `alive` 没变，也拒绝旧生命动作。道具挡住致死伤害并未结束生命，不重置正在进行的终极技。
- 视觉时钟与模拟分离，所有提示均不改变固定步长或输入归属。

## Risks / Trade-offs

- 穿透遮挡的光柱可能在密集场景抢眼 → 限于倒地期间，复活/离队立即移除，保持细柱与低透明度。
- 无头手机视口不代表真机触屏整局 → 分开记录合成截图与真人验收，后者保持待办。
