# Spec Delta

## MODIFIED Requirements

### Requirement: 共享 GPU 界面

正常可见游戏 UI SHALL 由共享 Three GPU 呈现路径绘制，支持按已验收能力选择 WebGL2 或 WebGPU；Web 与 SDL SHALL 共用页面、场景、效果语义与交互。迁移 MUST 保留已确认的样式、动画时序及交互，不以 WebGL 的能力下限限制 WebGPU 的执行方式。系统文本、文件面板与启动失败表面 SHALL 属于明确的平台边界。

#### Scenario: 两端进入同一页面

- **WHEN** Web 和 SDL 用户进入大厅、研究所、图鉴或对局窗口
- **THEN** 使用相同页面规则、状态和视觉设计，无独立维护的正式 DOM 游戏页面

#### Scenario: 同一页面选择不同图形后端

- **WHEN** 同一发布构建分别使用 WebGPU 和 WebGL2 打开正式页面与对局
- **THEN** 中文文字、裁剪、透明层级、模型、阴影、调色及动效保持已确认的表现，输入和危险提示完整，不因后端不同缺失效果

### Requirement: 上下文恢复后继续游玩

图形上下文或设备丢失与恢复 SHALL 保留可恢复的游戏状态，重新准备必要 GPU 资源并允许继续、放弃和重开；不将失效资源或旧异步完成结果带入新设备与下一局。丢失期间 SHALL 不推进本地模拟或补算失去的墙钟时间，联机恢复 SHALL 遵守既有状态同步规则。恢复失败 SHALL 明确反馈，不无限重建或假装继续呈现。

#### Scenario: 恢复后开始新局

- **WHEN** 对局遇到 context loss，恢复后继续，再放弃并重新出发
- **THEN** 世界与 UI 正常绘制，动态窗口可关闭，不出现跨 context 资源错误

#### Scenario: 编译期间设备丢失

- **WHEN** 页面或对局准备过程中设备失效，旧资源准备稍后完成
- **THEN** 旧完成结果不得激活页面或对局，新设备资源准备完整后才恢复交互与绘制

#### Scenario: 原生宿主重建图形资源

- **WHEN** SDL 呈现失败后成功重建上下文
- **THEN** 使用新上下文重建 GPU 资源，保持原应用与对局归属，随后返回大厅和再次出发仍可用

## ADDED Requirements

### Requirement: WebGPU 使用原生执行策略

WebGPU 呈现 SHALL 根据实测负载和设备能力采用适合该后端的数据驻留、并行处理与命令提交方式，不把能兼容绘制视为优化完成。采用 GPU 处理的工作负载 MUST 在真实场景中完成 GPU 数据消费闭环，不能以逐帧读回和 CPU 重算冒充 GPU 执行。WebGL 回退 SHALL 保持相同效果语义与可玩性，其能力限制不应强制 WebGPU 执行相同的低效路径。

#### Scenario: GPU 更新动态视觉数据

- **WHEN** 已启用 WebGPU 的视觉工作负载由 GPU 更新并供绘制使用
- **THEN** 绘制直接消费相应 GPU 结果，CPU 只提供必要的事件或参数；诊断能确认实际执行策略与上传/读回情况

#### Scenario: 后端缺少可选加速能力

- **WHEN** 当前后端没有某项可选加速所需能力
- **THEN** 选择该后端受支持的执行策略，保持效果与输入契约，诊断如实报告选择结果，不把 CPU 或 WebGL 路径标成 WebGPU 加速

### Requirement: 渲染优化保持画质与玩法边界

优化 SHALL 保持文字清晰度、已确认动效、危险反馈和本地玩家识别；呈现 SHALL 只读模拟。后端、分辨率、压缩格式和加速策略变化 MUST NOT 改写随机序列、碰撞、伤害、奖励或回放结果。界面与世界分辨率 SHALL 可独立管理，不因世界降分辨率使操作文字失去可读性。

#### Scenario: 高负载时调整渲染策略

- **WHEN** 混战触发已验收的动态分辨率或执行策略调整
- **THEN** 必要 UI 和危险区域完整，模拟结果不变；不以删减预警、缩短动画或降低字体质量取得性能收益

#### Scenario: 暂停世界但窗口仍在动

- **WHEN** 世界暂停且窗口过渡、输入反馈或通知仍需更新
- **THEN** 窗口正常动画，未变化的世界无需重绘；所有画面均不变时停止无意义的绘制，输入与状态检查仍可唤醒呈现

### Requirement: 性能与准备状态如实可观测

诊断 SHALL 区分后端、实际执行策略、CPU 提交与 GPU 耗时、世界/UI/阴影工作量、上传和内存估算，缺少计时能力时 MUST 报告不可用。资源准备 SHALL 确认当前设备上实际呈现所需的编译与上传成功，异步等待结束不等于成功；取消或失败不得激活页面或对局。优化证据 SHALL 来自同一内容和画质条件的对照，区分桌面视口、合成负载、原生 App 和真实手机。

#### Scenario: 设备不支持 GPU 计时

- **WHEN** GPU 时间查询不可用或结果失效
- **THEN** 显示该指标不可用，使用已定义的帧时间策略，不把 CPU 提交耗时或零值当作 GPU 耗时

#### Scenario: 预热后切换与重开

- **WHEN** 已准备的页面或对局首次展示、再次进入或经历设备恢复
- **THEN** 使用当前设备和真实绘制配置的有效资源，保留必要载入反馈；诊断可识别额外编译与上传，不以旧设备缓存命中掩盖未准备状态

#### Scenario: 着色器失败但异步等待正常结束

- **WHEN** 渲染或计算着色器编译失败，而底层异步等待仍正常结束
- **THEN** 对应准备任务进入失败状态并报告当前资源、阶段和设备归属，不将其记为就绪、不激活依赖页面，也不以换后端掩盖错误
