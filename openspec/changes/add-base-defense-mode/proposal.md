# Proposal

## Why

用户要在 poketone 里加一个新模式，暂名「据点」，从现有大厅进入。核心是 RimWorld 式的据点经营，加上抓宝可梦守据点；生存只是外壳。玩家操控人类训练师，在森林中央建据点，用球收服宝可梦，让它们打工、驻守，按预告抵御一波波兽群围攻。

整套模式很大，所以本 change 只做第一个可玩版本：单人，一小块地图，玩完「一天」，用来回答一个问题：这 20 分钟好不好玩。整个模式的方向已经和用户确认，本 change 一并记下，作为后续 change 的约束。

## What Changes

### 已确认的需求（用户 2026-11-16）

- 大厅新增模式入口。新模式有自己的世界数据、规则、存档和联机消息，和生存模式的进度（研究所、星星沙子、背包）完全分开。生存模式的 golden 回放每一步都不能变。
- 玩家操控人类训练师：训练师可以攻击；宝可梦是自动战斗的伙伴，用球捕获。行囊只按格子数限制。
- 没有「失败」：训练师阵亡后，行囊里的东西掉在原地，人在核心旁重生；核心被毁时据点「沦陷」，修好核心就恢复，世界不会被删除。
- 有昼夜循环。围攻按时间来，不一定在夜里，开始前一定有预告。
- 收服的宝可梦可以在据点打工，不做心情。
- 建造是核心支柱。全队共享一个据点，领地是以核心为圆心的圆。
- 被打坏的建筑在原地留下「虚影」，宝可梦自动修理、照原样重建；玩家可以在虚影上覆盖建造别的东西。
- 模拟规则不依赖镜头。镜头不做越肩视角，默认是高角度跟随；建造模式默认俯视。
- 读档后的结果必须和一直玩下去完全一致。
- 首版只做网页，原生端不显示这个模式的入口。

### 第一个可玩版本（本 change 交付）

- **准备**：先扩大三类按路径工作的检查，再把确定性数学、随机数和噪声搬进共享目录。三类检查是：CI 选测试、联机版本指纹、确定性数学的 lint 范围；测试里写死的模块路径也一并更新。
- **世界和存档**：单人，一块有边界的地图，用现有的森林地块和敌人。一个世界存档位，存档在本机，独立于生存进度；黎明和退出时自动保存。
- **训练师**：移动和攻击；用工具砍树、挖石头；行囊；阵亡后掉落物品并重生。
- **捕获和伙伴**：领地外有按种子生成、会重新出现的野生宝可梦，其中 3–5 种森林里已有模型的可以捕获，围攻中的敌人也能捕获；1 只出战伙伴；名册和收容箱；己方宝可梦被打倒后回球恢复。
- **建造**：网格地基、墙、门、工作台、守卫岗，以及据点核心。核心同时充当共享仓库。工作台可以制作精灵球。
- **工人**：工作只有守岗、伐木、搬运和重建四种，工人按属性和工作类型自动接活。
- **虚影**：建筑被毁留下虚影，可以修理和重建，可以覆盖建造；规划中、还没建的部件也用虚影表示。
- **一天**：昼夜时钟、黎明预告、一场围攻。敌人以核心为目标，会在绕路和破墙之间按代价选择。没在守岗的工人在围攻中躲到安全处。
- **核心与沦陷**：核心被毁则沦陷，共享仓库损失一次；制作和打工停下，防御照常工作；修好核心就恢复。
- **界面和视图**：据点世界视图，接入图形上下文丢失与恢复。GPU 界面包括 HUD、行囊、建造菜单、名册和收容箱、工作分配、预告，支持键鼠、触控和手柄。镜头为跟随式，建造模式俯视。

### 不在本 change（后续 change）

- 2–4 人联机、中途加入、成员身份、倒地与救起。
- 工作优先级、区域、生产单、种植、体力、据点等级和营地时代科技。
- 自由放置、守城高处、承重与坍塌。
- 6×6 区块世界、难度圈、共享探索、区域冻结、多个存档位、巢穴和后续时代。
- 围攻中的临时卡、伙伴的等级与进化、模拟放进后台线程。

这些后续项已经确认的方向见 design.md「整体方向」。

## Capabilities

### New Capabilities

- `base-world`：据点模式的世界边界。包括：
  - 与生存进度分开的世界存档
  - 读档与连续游玩一致
  - 昼夜时钟
  - 有边界的地图与采集点
  - 规则不依赖镜头
- `base-trainer`：训练师的移动、攻击和采集，开局物资，行囊容量，以及阵亡掉落与重生地点。
- `base-building`：领地、部件摆放、墙门通行、虚影、修理与重建、覆盖建造，以及建造模式的镜头与操作。
- `base-colony`：野生宝可梦、捕获、出战伙伴、名册与收容箱、己方宝可梦被打倒后的恢复、工人工作分配与接活规则、共享仓库、工作台制作。
- `base-raids`：围攻预告、围攻进行、攻城寻路、守卫岗、工人避险、围攻结束（击败或捕获）、核心与沦陷，以及沦陷后的恢复。

### Modified Capabilities

- `gpu-presentation`：
  - 新增大厅模式入口：网页显示，原生隐藏，进入时只提交一次。
  - 新增据点跟随镜头。
  - 修改「上下文恢复后继续游玩」：加上据点世界的场景。
- `simulation`：修改「画面不改变玩法」，把视野参数进入模拟限定为生存模式；据点模式遵守 base-world 的「规则不依赖镜头」。不改变生存模式的行为。

## Impact

- **新代码**：`src/base/`（模式会话、模拟、视图、GPU 界面）和 `src/shared/`（从 `src/run/sim/` 搬来的 `math.ts`、`rng.ts`、`noise.ts`）。
- **大厅和应用会话**：`src/ui/gpu/lobby.ts`、`src/app/session.ts`（`AppScreen` 新增模式路由）。
- **按路径工作的检查**：
  - `scripts/game-build.ts`（指纹只扫描 `src/run/sim/`）
  - `scripts/ci-scope.mjs`
  - `.oxlintrc.json`（确定性数学的 override 只覆盖 `src/run/sim/**`）
  - 测试里写死路径的 `mock.module`
- **平台存储**：网页需要新增异步的世界存档存储（IndexedDB）。现有的 `AppStorage` 是同步接口，不改。
- **资源**：
  - 训练师用原创形象，走低多边形 Tripo 多视图流程。
  - 建筑部件用 Blender 脚本生成，和树、灌木一样。
  - 新音效按 `docs/AUDIO.md` 用 ElevenLabs 生成。
- **文档**：
  - `PRODUCT.md` 的「不设训练师」改为只对本模式例外。
  - `README.md` 增加模式介绍。
  - `docs/README.md` 增加新规范的入口。
  - `docs/STATE-MACHINES.md` 增加模式会话和世界存档的生命周期。
  - 新增一份据点模式手册。
- **不受影响**：生存模式的规则、存档格式、golden 摘要和联机协议。

### 待确认（默认方案已写入本 change，批准提案即视为确认）

1. **模式名**：暂叫「据点」。代码和规范统一用 `base` 前缀，改名只改显示文本。
2. **PRODUCT.md 训练师例外**：「不设训练师」改成只对本模式例外。
3. **虚影规则**：按 base-building 规格执行。
4. **开局**：新世界开局没有宝可梦，训练师带基础工具和几个精灵球，第一个目标是抓到第一只。
5. **可捕获的宝可梦**：建议走路草、小拉达、波波、绿毛虫、六尾，实现时按模型和动作是否齐全最终确定。
6. **倒地与救起**：单人没有人能救起，所以这一项随联机 change 落地；第一个版本生命归零直接阵亡。
7. **数值**：一天的时长、围攻规模、领地半径、沦陷损失比例等，先用平衡模型算，再实测；用户已定的沦陷损失比例是 20%。
8. **按属性接活**：伐木只能由符合属性的宝可梦做，搬运、重建、守岗所有宝可梦都能做。
9. **预告内容**：首版写明时间、方向和规模；属性和随机词条以后再加。
10. **工人避险**：围攻期间所有非驻守的工人全部停工，包括远离敌人的修建，围攻结束后恢复。
11. **建造模式镜头**：可以离开训练师，在领地内自由平移。
12. **野生宝可梦**：只在被攻击后反击，被捕获或击败后过一段时间在领地外重新出现。
13. **被打倒的己方宝可梦**：回球恢复，保留原来的分配，恢复后自动继续。
14. **围攻结束**：捕获的围攻敌人也算退出这场围攻，但不掉落击败奖励；沦陷时剩下的围攻敌人撤离。
