# Design

## 原则

- **宝可梦玩家一看就懂**：每个事件、道具、规则都对应正作里的东西（招式、道具、特性、地点、名场面）。不发明需要读说明才懂的抽象机制。
- **风险与回报由玩家选择**：事件让玩家决定"现在去不去"，不是被动发生在身上。
- **复用现有设施**：节拍（`beats.ts`）、building 平台与站点（`stations.ts`）、宝箱卡、反应表（`reactions.ts`）、融合配方（`fusions.ts`）、研究所（`content/lab.ts`）。新东西优先写成内容表的数据。
- **硬约束**：确定性与联机一致（随机只用世界 rng，事件结果由房主结算）；普通生成默认在屏外（刻意在屏内要有理由）；不做商店；界面不常驻解释文字；新模型走 Tripo 低多边形流程，新音效走 ElevenLabs 流程。

### 共用约定

- **局外字段**只在 `extend-progress-v5` 定义，各 change 引用，不再另升进度版本。游戏已上线，进度从 v4 逐版升级，保留玩家数据。
- **世界状态**新增字段时提升世界快照版本（`sim/snapshot.ts`），快照不跨版本兼容；联机房间版本指纹随之变化。
- **开局配置** `RunConfig` 新增 `mode: "expedition" | "tower"`、`rules: readonly RuleId[]` 和每席的 `trainer`（`add-challenge-rules` 定义 `RuleId`）；种子码只编码这份配置能复现的内容。
- **路线**：`add-route-branches` 引入 `world.route`（已走过的地图）与路线位置；强度、经验与守卫成长改按路线位置读取。对战塔复用路线位置之后的强度外推。
- **出口**：`guide-field-exit` 的单个 `zone.exit` 在 `add-route-branches` 中扩展为多个出口，每个带目标地图与奖励标记。
- **内容表优先**：事件、交互点、天气、规则、徽章、解锁、羁绊奖励都是 `sim/content/` 下的数据表，带稳定字符串 ID，按 `src/run/sim/content/README.md` 登记，图鉴自动收录。
- **确定性与联机**：随机只用世界 rng；共享结果由房主结算；个人收益沿用 `multiplayer` 规范的个人奖励规则。
- **验收**：每个 change 改玩法必跑 test:sim 与 golden（有意变更重录）；改 GPU 界面看 1280×800 与 844×390；改平衡先跑解析模型。大版本发布前做一次两人联机全程试玩。
- **资产**：新模型走 Tripo 多视图流程并记录来源；新音效走 ElevenLabs 与母带流程，遵守舒适音量规则。

## 野外事件的整体方向

以下各期内容清单是总规划，后续 change 以它为起点细化。

## 第 1 期 野外事件（本 change）

用户 2026-11-17 确认全部内容（九种交互点、塔内幽灵、四种天气、异色）。下面是实现设计，代码位置以当前 `main` 为准。

### 1. 节拍：时间窗 + 种子抽取

现状：`StageZone.beats` 是 `[秒, Beat]` 固定表（`stages/beatTemplates.ts`），`updateDirector`（`director.ts`）每 tick 遍历，以 `` `${kind}@${at}` `` 写入 `world.spawn.fired` 去重，难度用 `earlyBy` 提前。

改为：

- `StageZone.beats` 的每项改成 `{ window: [from, to], beat }`。模板（`firstBeats` / `laterBeats` / `towerBeats`）把现有时刻扩成窗口，例如 150 → [130, 170]。
- 新增 `StageZone.events: { windows: readonly [number, number][]; pool: readonly EventId[] }`。每个窗口从池里抽一个，同一局（跨图）不重复。
- **进入区域时一次性排定**：`enterZone` / `createWorld` 用区域 rng 抽出时刻与事件，写入 `world.zone.schedule: { at: number; beat: Beat | { kind: "event"; id: EventId } }[]`（按时刻排序）。`updateDirector` 只按排好的表触发，`fired` 改为表内下标。排定结果是世界状态，随快照和联机下发，恢复后不重抽。
- `earlyBy` 继续作用于排定后的时刻。
- 已用过的事件记录在 `world.eventsUsed: EventId[]`，跨图保留，保证同局不重复。
- 新节拍放进 `beats.ts` 的 `beatRules`：
  - `horde`（群体遭遇）：同种 5 只围成一圈，复用 `spawnOnRing`，仍走屏外放置。
  - `outbreak`（大量出现）：60 秒内把某物种的生成权重提高（写 `world.spawn.outbreak: { species, until }`），该物种经验 ×1.5，异色概率 ×4。
- 事件（`EventId`）包括：两种新节拍、四种天气、"交互点觉醒"（让地图上一个休眠的交互点亮起，见 §3）。内容表 `content/events.ts`。

### 2. 天气

- 世界状态 `world.weather: { id: WeatherId; from: number; until: number } | null`。预告阶段（`from` 之前 5 秒）横幅 + 天空色变化；持续 75 秒；同时只有一种。
- 内容表 `content/weather.ts`：`{ id, name, stages: StageId[], element: { [type]: number }, chip?: { dps: number; immune: ElementType[] }, moves?: Partial<Record<MoveId, MoveTweak>> }`。
- 我们是自动瞄准、没有命中率，所以"必中"和"免蓄力"改写为数值：

| 天气   | 地图 | 属性修正（敌我同样） | 招式调整          | 持续伤害                                  |
| ------ | ---- | -------------------- | ----------------- | ----------------------------------------- |
| 大晴天 | 火山 | 火 ×1.3，水 ×0.7     | 日光束冷却 −40%   | 无                                        |
| 下雨   | 海岸 | 水 ×1.3，火 ×0.7     | 打雷、暴风次数 +1 | 无                                        |
| 沙暴   | 沙漠 | 岩石 ×1.2            | 无                | 每秒 1.5% 最大生命，岩石/地面/钢免疫      |
| 冰雹   | 冰川 | 冰 ×1.2              | 无                | 每秒 1.5% 最大生命，冰免疫；冰冻持续 +30% |

- 修正接入现有伤害路径：属性倍率在 `combat.ts` 的伤害计算处乘一次；招式调整在 `stats.ts` 的招式派生数值处读取；持续伤害作为一种不可减免、不打断施法的来源，走 `hurt.ts`，敌人同样承受（守卫只承受一半）。
- 第 3 期 `deepen-builds` 的天气招式、岩石道具和特性在此基础上延长或主动触发天气。

### 3. 地图交互点

**放置**：地图规格新增 `site` 平台（`PadSpec { tag: "site", radius: 2.5, count, maxSlope: 0.08 }`），各图数量 3–5 个。`furnishMap` 按区域内容表 `StageZone.sites` 用地图种子给每个平台分配种类。部分平台初始休眠，由事件"交互点觉醒"点亮。可玩性检查（`mapgen/playable.ts`）对 site 平台使用与站点相同的规则：站得下最大玩家身体、与出生点双向可达。

**状态**：`world.sites: Site[]`，`Site = { id, kind: SiteKind, x, z, state: "dormant" | "ready" | "busy" | "spent", until: number, owner: PlayerId | null, data }`。阻挡沿用站点做法：有实体的交互点（树、卡比兽）调用 `addCircleBlocker`。

**交互顺序**：`applyCommand` 的 `interact` 改为：救援 → 区域（地标/出口）→ 交互点 → 站点。`createRun.ts` 的 `interactPrompt` 使用同一顺序（`guide-field-exit` 已统一前两项）。交互点不会和站点、出口重叠（放置时保证间距）。

**结算**：交互、计时、生成与奖励都在共享世界里推进，由房主结算；同一 tick 多人交互只生效一次；掉落走现有 `Pickup` 与个人奖励规则。

**内容表** `content/sites.ts`（`SiteDef { id, name, stages, interact: "instant" | { channel: number }, rule }`），规则写在 `sim/sites/<kind>.ts`，一种一个模块：

| ID           | 名称         | 地图       | 规则                                                                                                                                                                            |
| ------------ | ------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `honey-tree` | 甜甜蜜树     | 森林、海岸 | 交互后 8 秒，在树旁掉下一只精英（赫拉克罗斯 / 凯罗斯 / 小卡比兽，按种子）；树先摇晃作为预兆。击败必掉宝箱                                                                       |
| `item-ball`  | 道具球       | 全部室外   | 一次生成 6–8 颗，走过去自动拾取：道具卡、树果或星星沙子；其中 1–2 颗是霹雳电球，玩家靠近 2 单位时 0.8 秒预警后自爆（照常伤害，可冲刺躲开）                                      |
| `snorlax`    | 睡着的卡比兽 | 森林、冰川 | 交互即"吹宝可梦之笛"，卡比兽醒来成为大型精英（生命为普通精英的 4 倍）。击败必掉吃剩的东西，背包满则改为大量树果                                                                 |
| `fishing`    | 钓鱼点       | 海岸       | 引导 2 秒（受击打断）。结果按权重：鲤鱼王 60%（少量星星沙子）、道具 30%、暴鲤龙精英 10%。每个钓鱼点 3 次                                                                        |
| `fossil`     | 化石挖掘点   | 沙漠       | 引导 4 秒（受击打断，进度保留）。完成后跳出化石翼龙精英，击败奖励一张保底稀有的宝箱卡                                                                                           |
| `raid-den`   | 团体战巢穴   | 全部室外   | 交互后巢穴中出现一只巨大化精英（体型 ×1.6，生命为头目），限时 60 秒。限时内击败得传说宝箱卡，超时它退回巢穴，无奖励                                                             |
| `spring`     | 治愈之泉     | 全部       | 全队回满生命，用一次后枯竭                                                                                                                                                      |
| `egg`        | 宝可梦蛋     | 全部室外   | 拾取的玩家背着蛋，移动累计 120 单位后孵化：若伙伴栏有空位，得到本图名单中的一只伙伴，否则得到稀有宝箱卡。倒下时蛋掉在原地                                                       |
| `glint`      | 闪光点       | 全部       | 地上每 2 秒闪一下，走过去自动拾取一件随机道具。不在小地图显示，要靠眼睛发现                                                                                                     |
| `ghost`      | 未识破的幽灵 | 紫苑塔     | 某层出现"幽灵"精英，没有西尔佛检视镜时伤害为 0、显示为黑影。检视镜由同层的另一个交互点（`silph-scope`，即时拾取，全队共享）提供；识破后显示真身（嘎啦嘎啦），击败奖励传说宝箱卡 |

奖励卡复用宝箱卡（`source: "chest"`，`MIN_UPGRADE_RARITY`）；"传说宝箱卡"新增保底稀有度参数。所有数值放在 `content/params/sites.ts`，由解析模型估算每图额外收益（`balance:model` 新增"事件收益"项）。

### 4. 异色宝可梦

- `Enemy.shiny: boolean`。普通敌人（非精英、非守卫）生成时以 `SHINY.chance`（1/400，大量出现时 ×4）判定，每图最多 1 只。
- 训练师夜苇的被动（`add-trainer-support`）：队伍里有任一名在场玩家选了夜苇时，`SHINY.chance` ×1.5，多人选也不叠加；每图上限不变。
- 异色个体生命 ×3，出现时发出事件 `{ t: "shiny" }`（闪光 + 音效 + 边缘消息），25 秒后逃离（走向最近的地图边缘后移除，不计击败、不掉落）。
- 击败：全队每人星星沙子 +`SHINY.stardust`，事件 `{ t: "shiny-caught", species }`。
- 图鉴：结算时把本局的 `seen` / `defeated` / `shiny` 计数写入进度 v5 的 `dex`（`extend-progress-v5`）。本局计数存在 `Player.dex`（每人自己的击败，`seen` 为全队可见），和其他局外奖励一起只入账一次。
- 画面：异色用该物种模型的异色配色（贴图调色板替换，在 `view/shiny.ts` 注册每个物种的异色调色参数，无需新模型）。图鉴共用这套参数，`add-shiny-looks` 继续复用它给伙伴换装。

### 5. 新物种与资产

- **新模型（Tripo 多视图流程，约 40 积分/只）**：赫拉克罗斯、凯罗斯、小卡比兽、卡比兽、鲤鱼王、暴鲤龙、化石翼龙、嘎啦嘎啦（幽灵真身）。幽灵黑影用嘎啦嘎啦的剪影材质，不单独建模。
- **场景模型**（Blender 脚本，与树木同流程）：甜甜蜜树（森林树木变体加蜂蜜）、道具球、钓鱼点木桩、化石岩层、巢穴、泉水、蛋、闪光点用粒子即可。
- **敌人定义**：新物种写进 `content/enemies.ts`，只在事件中生成，不进普通名单；图鉴照常收录。
- **音效（ElevenLabs，按 `docs/AUDIO.md`）**：天气起始（晴/雨/沙/冰各一）、天气循环底噪 4 条、宝可梦之笛、钓鱼收线、挖掘、巢穴开启、异色闪光、蛋孵化、霹雳电球预警。遵守舒适音量规则，战斗提示不用铃声。

### 6. 界面

- 天气：预告与开始用现有横幅位；HUD 角落显示天气图标与剩余时间条（图标，不写说明）。
- 交互点：小地图与罗盘显示图标（闪光点除外）；靠近时显示交互提示，复用站点提示组件。引导类交互显示进度环。
- 异色：边缘消息位提示一次；小地图上异色个体显示闪光点。

### 7. 联机与快照

- 新增世界字段：`zone.schedule`、`eventsUsed`、`weather`、`sites`、`spawn.outbreak`、`Enemy.shiny`、`Player.dex`、`Player.egg`。世界快照版本加一。
- 交互点的引导者是交互的玩家本人；房主结算引导是否完成或被打断。

## 第 2 期 分岔路线（参考以撒的结合和杀戮尖塔）

- 守卫倒下处开出 **2 个出口**（偶尔 3 个），每个出口上方显示下一张地图和一个**奖励标记**。
- **路线分层**：森林 → {沙漠 | 海岸} → {冰川 | 火山} → 紫苑塔；下一层没走的那张图在下一局可能走到。敌人强度改为按**路线位置**计算，不再按地图计算（平衡模型要同步）。
- **奖励标记**（像以撒的特殊房间）：
  - 宝箱更多
  - 精英巢（精英更多，奖励翻倍）
  - 宝可梦中心（入图时回满血，并多一个引梦貘人）
  - 研究资料（星星沙子更多）
  - 耿鬼的交易：对应以撒的恶魔房。用最大生命换一件传说道具。幽灵系的诅咒交易在宝可梦里说得通。
- **守卫奖杯**：守卫倒下时，除了出口还出现 3 个台座，三选一，可以拿道具、招式强化或特性（对应以撒的 Boss 道具）。
- **地图词条**（对应以撒的诅咒，用宝可梦里的场景表达）：
  - 黑暗洞穴：视野变小，带闪光的招式或道具能照亮
  - 浓雾：小地图失效，拿到清除浓雾就恢复
  - 头目出没：精英更多

## 第 3 期 构筑深度

只用正作已有的机制：

- **誓约组合招式**（五代）：
  - 草之誓约 + 火之誓约 → 火海（持续灼烧地面）
  - 水之誓约 + 火之誓约 → 彩虹（附加效果概率提高）
  - 草之誓约 + 水之誓约 → 湿地（减速）

  这正好接上已有的反应表（燃烧、潮湿）。用户确认：誓约组合只在联机时由两名玩家各出一招触发（正作每只御三家只学自己属性的誓约），与融合无关，融合仍只限本线招牌（以 `deepen-builds` 为准）。

- **天气构筑**：
  - 求雨、大晴天、沙暴、冰雹作为招式。
  - 潮湿岩石、炽热岩石作为延长天气的道具。
  - 特性与天气联动：叶绿素、悠游自如、太阳之力。
- **双特性与隐藏特性**：每条线有正作的两个特性，进化时二选一，隐藏特性从事件或守卫奖杯获得。例如：
  - 小火龙：猛火 / 太阳之力
  - 杰尼龟：激流 / 雨盘
- **不变之石 + 进化奇石**：持有不变之石就不进化，换来进化奇石的大幅防御加成。"要不要进化"成为一个真选择，玩家都懂这个梗。
- **通信进化**：腕力、鬼斯通在正作里靠通信交换进化。联机时两名玩家在交换点交换后进化；单人用阿尔宙斯里的联系绳道具（事件或奖杯获得）。
- **进化石**：皮卡丘在雷之石卡出现时可以选择进化成雷丘或保持皮卡丘，两者走不同的数值方向。
- ~~道具组合效果~~：已删除。正作没有“集齐道具触发额外效果”的规则，不符合“宝可梦玩家一看就懂”的原则（`deepen-builds` 已移除）。

## 第 4 期 挑战规则、徽章与研究所

### 挑战规则（类似哈迪斯的热度）

出发前勾选规则，每条有危险度。总危险度提高星星沙子倍率，达到门槛时获得**道馆徽章**（共 8 枚，作为长期目标，在研究所展示）。规则用玩家熟悉的玩法：

- **Nuzlocke**：倒下就不能复活，联机时队友救援失效
- **等级上限**：每图有等级上限，超出的经验转成星星沙子
- **禁止携带道具**：对战设施规则
- **单属性**：只出与伙伴同属性的招式卡
- **头目化**：所有精英带头目强化
- **异常天气**：天气事件频率翻倍

### 研究所扩展

- **图鉴研究**（阿尔宙斯的研究等级）：击败、遭遇、异色会累积每种宝可梦的研究等级。达到满级后图鉴显示完整数据，并解锁该物种相关的事件或掉落。
- **内容解锁取代纯数值**：新的交互点、出口奖励标记、隐藏特性、挑战规则，通过研究解锁（参考以撒靠解锁扩充内容池）。保留现有数值项，但不再是唯一的成长方向。
- **界面风格化**：研究所做成实验室场景，包括书架上的研究卷宗、实验台上的强化装置、墙上的徽章盒。研究树按"卷宗"分类，节点像道具或徽章。设计流程按 `DESIGN.md` 和 impeccable 进行，只由 Claude 做设计，要有真实截图验收。
