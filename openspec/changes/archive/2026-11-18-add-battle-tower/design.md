# Design

## 所属版本

大版本「野外与路线」第 10 项，共用约定见 [野外与路线规划](../archive/2026-11-18-add-field-events/design.md) 总表。依赖 `extend-progress-v5`、`add-route-branches`、`guide-field-exit`。

## 模式与开局

- `RunConfig` 新增 `mode: "expedition" | "tower"`（总表共用约定）。对战塔模式下 `stage` 不用于选图，楼层地图由种子决定。
- 解锁：进度 `clears` 任一难度大于 0。难度沿用远征的三档与解锁规则。
- 从 1 级、空构筑开始；研究所加成与背包照常生效（与远征一致）。

## 楼层

- 每层是一个区域，复用现有的区域准备与切换（`prepareZone` / `enterZone` 与载入屏障）。地图从六张地图中按 `mixSeed(seed, floor)` 抽取，连续两层不重复；地图种子同样由层数混合。
- 普通层：场地时长 `TOWER.floorSeconds`（150 秒），节拍使用该地图模板压缩到层时长后的时间窗（与 `add-field-events` 的时间窗排定共用）。计时结束时以地标位置调用 `clearZone`（`currentZone.ts`），出口开在地标处；没有召唤守卫这一步。在出口交互（`interactInZone` 的 leave 分支）进入下一层。对战塔不设塔顶，`nextField` 始终有下一层。
- 守卫层（第 7、14、21… 层）：没有场地计时，开局即生成该地图守卫（不需要在地标召唤），按楼层强化；守卫倒下处开出口（`guide-field-exit`）。击败后发放一次守卫奖励卡，并全队回复 50% 生命。
- 层间保留等级、构筑、生命与伙伴；倒下规则与远征相同（全队倒下即失败）。
- 野外事件（`add-field-events`）在对战塔中照常抽取；天气按所在地图。远征里“同一局不重复”的规则在对战塔里改为“每 7 层一轮”：每到守卫层后清空已抽记录，池子在一轮内仍不重复；一轮内池子抽空时该窗口不出事件。测试在前 50 层覆盖多轮抽取。
- 抽到紫苑塔地图时，出口同样进入下一层，不结束对局。

## 强度外推

现有路线强度来自 `CAMPAIGN_GROWTH` 与 `CAMPAIGN_HP_CLOCK`（`content/params/campaign.ts`），（后者由 `tune-map-entry-pace` 改名为 `CAMPAIGN_ENTRY_CLOCK`）由 `add-route-branches` 改为按路线位置读取。对战塔把楼层折算为路线位置：

- `position(floor) = (floor − 1) / 7`，即每 7 层前进一张图。
- `position ≤ 3`（四步路线之内）：在 `ROUTE_GROWTH` 相邻两步之间线性插值，入图时钟 `ROUTE_ENTRY_CLOCK` 同理。
- `position > 3`：从最后一段（第 2 → 3 步）的斜率线性外推，每项再乘以各自的斜率系数 `TOWER.slope`。不截顶：强度一直线性增长，队伍终究会倒下，这就是无尽的终点。线性增长在任何现实层数下都是有限值。
- 守卫层的守卫生命与伤害额外乘以 `TOWER.guardianBonus`（1.25），生命再乘 `TOWER.guardianHealthBonus`（2.56），只拉长战斗、不提高单次命中伤害。
- 校准（2026-11-18，`bun run balance:tower`，三个种子、average 画像）：斜率系数 `hp/dmg/guardianHp/clock` 为 `4/75/8/1`，普通难度中位通过约 20–27 层，到第 50 层累计通过率不高于 0.42%。后段伤害增长较陡，属解析模型结果，需真人试玩确认手感。
- 只用加法和乘法，不引入 `exp` / `pow`；参数放在 `content/params/tower.ts`，`balance:model` 新增对战塔分段，估算第 1–50 层每 7 层的压力指数与通过时间（用户 2026-11-17：只模拟 50 层）。

## 数值边界（`docs/research/DETERMINISM.md`）

- `sim/math` 的 `sin` / `cos` 定义域为 |x| ≤ 2^20·π/2 ≈ 1.65e6，超出抛 `RangeError`。现有输入是 `world.time × 频率 + 实体 id`（`status.ts`、`movement.ts`）。
- `exp` 定义域 |x| ≤ 708；只在超时暴走（`rampageFactor`）中使用，层计时结束后才会开始暴走，对战塔普通层计时结束即开出口，暴走只在玩家不进出口时出现，几分钟内结束对局，不会接近上限。
- 不设塔顶（用户确认）。100 层约 1.6e4 秒、实体 id 约 6e4，三角函数输入约 1e5，仍在定义域内；但无尽意味着没有保证，所以在这两处调用里把输入折回：`|x|` 超过 `PHASE_FOLD`（2^19）时减去 2π 的整数倍。只有超过阈值才折，正常远征（输入远小于阈值）的结果逐位不变，远征 golden 不变。折回只用确定性的乘减，跨引擎一致。
- `exp` 只在暴走中出现，输入是暴走开始后的时间，与层数无关。
- 新增测试：强度函数在第 50 层的值有限且符合外推；三角函数路径以远超阈值的时间与 id 调用，不抛错且结果有限；阈值以下的输入与折回前逐位相同。

## 联机

- 楼层、出口、守卫与奖励都在共享世界里，由房主结算；离开沿用远征规则：任一存活玩家在出口交互，且 `canLeave` 成立（站点对话已关闭）时全队进入下一层。
- 每位玩家结算时只更新自己伙伴的 `tower` 记录。

## 记录与结算

- 成绩统一用“通过的层数”：离开某层出口才算通过该层，第 1 层就倒下为 0。结算界面、`RunResult`、进度和测试都用这个数。进度 v5 `tower[starter]`：层数更高时覆盖；层数相同且难度更高时覆盖。
- 对战塔的星星沙子与经验奖励沿用远征规则，按击败数结算；不另设对战塔货币（PRODUCT.md：不加商店）。

## 界面

- 大厅：模式选择加入"对战塔"，未解锁时显示锁定状态；选中后显示该伙伴的最高层。
- HUD：路线进度位置显示"第 N 层"；守卫层使用现有守卫提示。
- 新增界面文字需要通过 `test:ui` 字形检查。

## 不做

- 不做排行榜、服务器或联网成绩。
- 不做对战塔专属商店或货币。
- 不做中途存档后跨版本继续（快照不跨版本兼容）。
