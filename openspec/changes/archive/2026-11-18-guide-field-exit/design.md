# Design

## Context

动机和范围见 [proposal](proposal.md)。地标原本同时承担召唤与离开，清区提示因此容易把玩家引回远处。出口位置会影响模拟交互、地图提示、快照与联机，必须由共享世界保存。

## Decisions

- `ZoneState.exit` 保存实际出口坐标。守卫倒下后通过 `currentZone.ts` 检查净空与双向可达，优先落在倒下处，再环形搜索，最终使用已验证的地标位置。只在画面移动光柱会使交互与地图提示脱节，因此世界和视图读取同一坐标。
- 净空使用地图内最大玩家身体，避开站点的交互范围。只用当前形态会在拾取守卫经验并进化后出现新重叠；出口生成不能依赖奖励抵达先后。
- 地标在清区后失去区域交互，`zoneAction` 统一给命令和 HUD 提供目的地。离开沿用已有奖励收取与换区准备屏障，避免新增第二条结算路径。
- 世界光柱、小地图与大地图标记、贴边指向和罗盘共用模拟出口；清区地标熄灭。共享 GPU 绘制与平台输入边界见 `gpu-presentation` 主规范和 `docs/STATE-MACHINES.md`。
- 世界快照版本提升到 5，恢复时检查出口坐标、边界与区域阶段。不同版本直接拒绝，不迁移临时世界快照；本机进度版本不受影响。

## Risks / Trade-offs

- 守卫死亡落点可能位于悬崖、障碍或站点附近 → 使用最大身体净空、双向可达和站点距离筛选，保留地标兜底。
- 出口位置可能改变回放末段路径 → 保留胜利、进化与捕获覆盖，只有摘要有意变化时重录，不因代码移动重录。
- 受控守卫场景可验证交互和提示，但不能代表自然通关或物理触屏 → 将正式 GPU 页面、合成输入和设备验证分别记录在临时 QA 证据中。

## Migration Plan

代码、世界快照版本和提示一起发布；世界快照不跨构建兼容。回退时整体回退这一组改动，玩家本机进度继续沿已发布版本迁移规则读取。
